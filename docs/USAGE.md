# OriaTunnel 使用指南

OriaTunnel 是用于管理 SSH 端口转发的桌面应用。你可以在连接图或转发列表中管理多个服务，分别启动、停止和查看连接状态。

本指南面向日常使用，包含添加主机、创建转发、常见场景、配置迁移和问题排查。构建与运行方法见 [README](../README.md#启动)。当前为 Windows/macOS 开发版，仓库尚未发布安装包；具体设备验证范围见 [项目状态](PROJECT_STATUS.md)。

## 开始之前

准备好以下信息：

| 信息               | 用途                       | 示例                      |
| ------------------ | -------------------------- | ------------------------- |
| SSH 主机地址和端口 | 建立 SSH 连接              | `ssh.example.com:22`      |
| SSH 用户名         | 登录服务器                 | `devuser`                 |
| 认证方式           | 密码、私钥或系统 SSH Agent | 选择本机私钥文件          |
| 服务地址和端口     | 指定实际要访问的服务       | 服务器的 `127.0.0.1:3000` |

文中的域名、IP、用户名和端口均为示例，请替换为自己的配置。示例假设对应服务已经启动；OriaTunnel 默认只建立转发，不负责安装或启动数据库、网页服务等应用。

**SSH 端口与服务端口是两回事。** SSH 端口用于建立加密隧道，服务端口用于选择隧道另一端要连接的服务。SSH 登录成功后，转发还需要服务器允许，并且目标服务可从相应一侧访问。

## 选择 L、R 还是 D

| 方式                       | 使用目的                 | 监听在哪里 | 谁连接目标 | 客户端如何使用               |
| -------------------------- | ------------------------ | ---------- | ---------- | ---------------------------- |
| **L · 访问远端服务**       | 本机访问一个固定远端服务 | 此电脑     | SSH 服务端 | 访问本机监听端口             |
| **R · 让远端访问本地服务** | 远端访问一个固定本机服务 | SSH 服务端 | 此电脑     | 在远端访问监听端口           |
| **D · 动态 SOCKS5 代理**   | 借 SSH 主机访问多个目标  | 此电脑     | SSH 服务端 | 将软件配置为使用 SOCKS5 代理 |

- 访问一个数据库、网页后台或 VNC 服务：通常选择 **L**。
- 让服务器访问你电脑上的开发服务：选择 **R**。
- 用浏览器访问多个内网站点或服务器上的多个端口：可以选择 **D**。

**`127.0.0.1` / `localhost` 指哪台电脑，取决于谁连接目标。** L 的目标回环地址指 SSH 服务端；R 的目标回环地址指此电脑；D 请求中的目标回环地址在请求确实经过代理时指 SSH 服务端。D 的浏览器绕过代理问题见后文。

## 添加和管理 SSH 主机

### 从本机 SSH 配置添加

1. 点击「添加主机」，查看自动发现的候选主机，也可以搜索名称或地址。
2. 选择需要的主机并添加。
3. 查看主机详情中的地址、端口、用户名、认证方式及配置诊断。

应用读取本机 SSH 客户端配置并跟随 `Include`，包括用户的 `~/.ssh/config`（Windows 下为 `%USERPROFILE%/.ssh/config`）。设置中可以添加额外的 SSH 配置文件，并控制「自动检测配置变化」；也可以手动刷新。

发现和同步仅解析配置，不执行配置命令、不登录主机，也不会自动运行配置中的 `LocalForward`、`RemoteForward` 或 `DynamicForward`。**添加主机后，还需要在 OriaTunnel 中创建转发规则。**

来源主机的连接字段由 SSH 配置文件管理，在应用内只读。要修改地址或用户名，可以编辑源文件并刷新，或使用「创建可编辑副本」另存为手动主机。显示名称与标签可以在应用内单独设置。

### 手动添加

1. 在「添加主机」中转入手动添加。
2. 填写名称、SSH 主机地址、SSH 端口和用户名。地址栏只填主机名或 IP，端口填在单独字段中。
3. 选择认证方式：自动、密码、私钥或系统代理。使用私钥时选择本机文件，可添加多个候选私钥。
4. 按需设置标签、跳板主机、超时及保活参数。
5. 保存；需要验证时选择「保存并测试」，或保存后在主机详情点击「测试连接」。

例如，连接命令为 `ssh -p 1020 devuser@ssh.example.com` 时，对应字段为：

| 字段         | 填写内容          |
| ------------ | ----------------- |
| 名称         | 我的服务器        |
| SSH 主机地址 | `ssh.example.com` |
| SSH 端口     | `1020`            |
| 用户名       | `devuser`         |

系统代理指 **SSH Agent 认证代理**，用于使用已加载的密钥完成 SSH 认证，与 D 的 SOCKS5 网络代理不同。

### 测试连接、认证与指纹

「测试连接」只验证 SSH 连接、认证和服务器身份，不创建转发、不执行远程命令，也不代表某个业务服务已经可用。

首次连接时，根据管理员或可信渠道提供的信息核对主机密钥指纹；使用跳板时，每一跳都要分别核对。已信任的指纹发生变化时，应用拒绝连接，应先确认服务器是否重装或更换了主机密钥。

密码或加密私钥的口令在认证弹窗输入。Windows/macOS 可主动勾选「记住密码」，仅在实际密码认证成功后写入当前用户的系统凭据库；私钥口令不保存。已有保存密码时可留空复用，也可点击「清除已保存密码」。取消勾选不会删除已经保存的密码。

### 跳板与主机维护

目标主机不能直连、需要经过堡垒机时，先添加跳板主机，再在目标主机的 ProxyJump 路线中按顺序选择。每一跳使用自己的认证与指纹校验，转发目标仍由最终 SSH 服务端访问。

主机页支持搜索、筛选与分组。删除主机时会列出并一并删除关联转发、停止其连接；被其他已添加主机用作跳板的主机，需要先修改相关路线，进行中的主机测试也需先停止。删除配置来源主机只移除应用内引用，不修改本机 SSH 配置文件。

## 创建和管理转发

1. 点击「新建转发」，填写便于识别的名称，选择已添加的 SSH 主机。
2. 选择 L、R 或 D，并按下面的场景填写监听和目标字段。字段中的地址只填主机名或 IP，不填 `http://`、路径或端口。
3. L/R 可以选择 HTTP、HTTPS 或 VNC 服务协议；默认不选，再次点击可取消。D 没有固定服务入口，协议选择不可用。
4. 初次使用可以保留高级参数默认值，包括「不运行远程命令」。
5. 点击「保存」只保存规则；点击「保存并启动」继续认证和建立转发。
6. 等待规则显示「监听中」，再使用浏览器、数据库客户端或代理客户端访问。

服务协议用于「打开服务」快捷入口，**不会修改服务端口、安装服务、把 HTTP 转成 HTTPS，或改变转发的数据内容**。VNC 需要系统已有注册的客户端；noVNC 等网页入口应按实际服务选择 HTTP/HTTPS。

连接图中每条转发地址路径右侧的「打开服务」按钮，在规则就绪且入口可用时打开对应程序。R 的远端回环监听无法从此电脑直接打开；D 则需要自行配置客户端代理。

### 日常操作

- **详情**：查看实际状态、监听路径、认证方式、流量、活动连接及重试信息。
- **编辑**：修改运行中规则的连接参数会提示「保存并重新连接」，已有连接会中断；名称、颜色和服务协议修改不重连。
- **从此转发新建**：以已有规则为起点创建另一条规则，保存前检查监听端口是否冲突。
- **停止**：关闭监听、断开该规则已有业务连接，并取消重试。
- **删除与撤销**：删除会停止对应连接；本次应用运行内可撤销最近 20 次删除操作。恢复的主机和规则保持停止，自动连接关闭。

顶栏「全部开启／全部停止」作用于当前工作区全部规则。转发页可选择部分规则批量启动、停止或删除。批量启动按主机收集认证信息，各规则独立建立连接；结果中的「已受理」表示请求已提交，是否成功仍以各规则实际状态为准。

连接图和转发列表使用同一组规则。拖动节点可整理布局；此电脑上的端口也可拖到四边，双击端口可恢复自动排列。布局调整不会改变转发方向或连接参数。

## 场景一：访问服务器上的网页或数据库（L）

假设 SSH 主机上的网页后台只监听 `127.0.0.1:3000`，希望从此电脑的浏览器访问。

| 转发字段                      | 填写内容                      |
| ----------------------------- | ----------------------------- |
| 转发方式                      | L · 访问远端服务              |
| SSH 主机                      | 已添加的服务器                |
| 本机监听地址                  | `127.0.0.1`                   |
| 本机监听端口                  | `13000`                       |
| 目标地址（由 SSH 服务端访问） | `127.0.0.1`                   |
| 目标端口                      | `3000`                        |
| 服务协议                      | HTTP（假设服务本身使用 HTTP） |

保存并启动后，在此电脑打开：

```text
http://127.0.0.1:13000
```

```text
此电脑浏览器 → 本机 :13000 → SSH 隧道 → 服务器 127.0.0.1:3000
```

浏览器无需设置代理。服务器不需要把 `3000` 暴露到公网，只需 SSH 服务端能够访问该端口且允许转发。

同样的方法也适用于以下服务，每个固定目标创建一条 L 规则：

| 服务       | 本机监听示例      | 目标示例（由 SSH 服务端访问） | 客户端连接方式                                   |
| ---------- | ----------------- | ----------------------------- | ------------------------------------------------ |
| PostgreSQL | `127.0.0.1:15432` | `127.0.0.1:5432`              | 数据库客户端连接 `127.0.0.1:15432`，不选服务协议 |
| 内网网页   | `127.0.0.1:18080` | `10.20.0.15:8080`             | 浏览器打开 `http://127.0.0.1:18080`              |
| VNC        | `127.0.0.1:15900` | `127.0.0.1:5900`              | VNC 客户端指定主机 `127.0.0.1`、端口 `15900`     |

数据库或 VNC 自身的登录认证仍由对应客户端处理。如果网页会重定向到内部域名，或依赖特定域名的证书与 Cookie，还需处理应用自己的地址配置；仅转发端口不会改写网页或证书。

## 场景二：让服务器访问本机开发服务（R）

假设此电脑已运行 `127.0.0.1:3000` 的 HTTP 开发服务，希望 SSH 服务器上的程序访问它。

| 转发字段                 | 填写内容               |
| ------------------------ | ---------------------- |
| 转发方式                 | R · 让远端访问本地服务 |
| SSH 主机                 | 已添加的服务器         |
| SSH 服务端监听地址       | `127.0.0.1`            |
| SSH 服务端监听端口       | `18080`                |
| 目标地址（由此电脑访问） | `127.0.0.1`            |
| 目标端口                 | `3000`                 |

启动后，**在 SSH 服务器上**访问：

```text
http://127.0.0.1:18080
```

```text
服务器程序 → 服务器 :18080 → SSH 隧道 → 此电脑 127.0.0.1:3000
```

如果希望其他电脑也能通过服务器访问，远端监听需要使用允许外部访问的地址，同时满足 SSH 服务端的 `GatewayPorts`、`AllowTcpForwarding`、`PermitListen` 等策略、网络映射及防火墙要求。**R 显示「监听中」不等于已经获得公网入口**；共享 IP 或 NAT 环境仍可能需要管理员额外映射端口。

## 场景三：通过 SSH 代理访问多个服务（D）

D 在此电脑提供一个 SOCKS5 代理入口，由使用代理的软件在每次请求时指定目标地址和端口。

### 建立代理

| 转发字段     | 填写内容               |
| ------------ | ---------------------- |
| 转发方式     | D · 动态 SOCKS5 代理   |
| SSH 主机     | 能访问目标服务的服务器 |
| 本机监听地址 | `127.0.0.1`            |
| 本机监听端口 | `1080`                 |

D 不填写固定目标。保存并启动，等待「监听中」。

### 配置浏览器或其他客户端

在支持 SOCKS5 的浏览器代理设置或代理工具中填写：

```text
代理类型：SOCKS5
代理地址：127.0.0.1
代理端口：1080
代理认证：无
```

使用内网域名时，启用客户端的“通过 SOCKS5 代理解析 DNS”或等效选项，使客户端把域名交给代理。SSH 登录密码只在 OriaTunnel 认证时输入，不填入 SOCKS 代理的用户名或密码。

应用不会自动修改浏览器或系统代理。客户端必须实际使用该代理，且目标不能命中其直连或绕过规则。不同客户端的设置入口与能力不同，请以客户端文档为准。

### 访问不同目标

假设 SSH 服务端能够访问以下内网服务，浏览器使用代理后可直接访问：

| 服务     | 浏览器地址               |
| -------- | ------------------------ |
| 网页后台 | `http://10.20.0.15:3000` |
| 文件服务 | `http://10.20.0.15:8080` |
| 监控面板 | `http://10.20.0.16:9000` |

```text
浏览器 → 此电脑 SOCKS5 :1080 → SSH 隧道 → SSH 服务端 → 本次请求的目标
```

`1080` 是代理入口，`3000`、`8080`、`9000` 才是服务端口。浏览器地址栏不填写 `http://127.0.0.1:1080`，因为 SOCKS5 入口本身不是网页服务。

### 服务只监听服务器的回环地址怎么办？

如果服务只监听 SSH 服务端的 `127.0.0.1:3000`，SOCKS5 目标应为 `127.0.0.1:3000`，浏览器地址为 `http://127.0.0.1:3000`。**只有该请求确实经过代理时，才会连接服务器的回环地址。**

浏览器可能默认让 `localhost`、`127.0.0.1`、`::1` 绕过代理，结果连接的是此电脑。仅清空可见的“代理例外”列表，也未必能取消浏览器的隐式绕过。Chromium 的相关规则见其 [官方代理说明](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md#implicit-bypass-rules)。

处理方式：

1. 如果服务也监听服务器的网卡地址，使用 SSH 服务端实际能访问的该地址，并确认客户端没有绕过它。
2. 如果客户端支持让回环目标经过 SOCKS5，按客户端说明配置；这会改变该客户端访问本机地址的行为，使用结束后恢复原代理配置。
3. 如果只需访问几个固定端口，改用 L 转发，浏览器无需配置代理。

### 用 curl 单独确认代理路径

在此电脑的终端执行以下命令，需要已安装 curl，并已启动本节的 D 转发与服务器上的 HTTP 服务：

```sh
curl --max-time 15 --noproxy "" --socks5-hostname 127.0.0.1:1080 http://127.0.0.1:3000/
```

Windows PowerShell 中使用原生程序名 `curl.exe`，避免同名别名；旧版 PowerShell 对空字符串参数的传递可能不同，可在命令提示符（cmd）中运行同样的 `curl.exe` 命令。

`--socks5-hostname` 指定 SOCKS5 代理并将目标域名交给代理，`--noproxy ""` 清空本次命令的代理绕过列表，`--max-time 15` 限制等待时间。参数定义见 [curl 官方手册](https://curl.se/docs/manpage.html#--socks5-hostname)及 [noproxy 说明](https://curl.se/docs/manpage.html#--noproxy)。

预期收到服务器上该 HTTP 服务的响应；如果 curl 可用而浏览器不可用，优先检查浏览器的代理类型、端口和绕过规则。

## 场景四：共享 IP，只分配一个 SSH 端口

假设平台给你分配了 `10.0.0.8:1020`，这是一条映射到你所用服务器 SSH 服务的入口。`10.0.0.8` 在此仅为示例私网地址，不表示公网 IP；关键是此电脑可以到达它，并能通过 `1020` 建立 SSH 连接。

服务器上的多个 HTTP 服务分别监听 `127.0.0.1:3000`、`:8080`、`:9000`，没有额外对外端口。

### 主机填写方式

| 主机字段     | 填写内容              |
| ------------ | --------------------- |
| SSH 主机地址 | `10.0.0.8`            |
| SSH 端口     | `1020`                |
| 用户名       | 平台分配的 SSH 用户名 |

### 方案 A：为固定服务分别创建 L 转发

三条规则均选择上述 SSH 主机：

| 本机监听          | 目标地址（由 SSH 服务端访问） | 目标端口 | 此电脑浏览器访问         |
| ----------------- | ----------------------------- | -------- | ------------------------ |
| `127.0.0.1:13000` | `127.0.0.1`                   | `3000`   | `http://127.0.0.1:13000` |
| `127.0.0.1:18080` | `127.0.0.1`                   | `8080`   | `http://127.0.0.1:18080` |
| `127.0.0.1:19000` | `127.0.0.1`                   | `9000`   | `http://127.0.0.1:19000` |

不需要浏览器代理，也不需要平台额外开放三个服务端口。每条规则独立连接同一个 SSH 入口。

### 方案 B：一条 D 转发承载多个服务请求

选择上述 SSH 主机，建立本机 `127.0.0.1:1080` 的 D 转发，再按上一节配置浏览器 SOCKS5 代理与回环目标代理行为。之后分别访问服务器的三个服务：

```text
http://127.0.0.1:3000
http://127.0.0.1:8080
http://127.0.0.1:9000
```

```text
浏览器 → 本机 SOCKS5 :1080 → SSH 入口 10.0.0.8:1020
                              ├─ 服务器 127.0.0.1:3000
                              ├─ 服务器 127.0.0.1:8080
                              └─ 服务器 127.0.0.1:9000
```

所有这些请求都可通过 `1020` 建立的 SSH 隧道传输。不要把共享入口的 `10.0.0.8:3000` 当作该服务器的服务地址；共享入口不一定有这些端口映射。

如果 `1020` 实际只提供 HTTP、RDP 或其他非 SSH 服务，就不能用它建立 SSH 转发。如果 SSH 登录落在容器中，目标 `127.0.0.1` 指该 SSH 服务所在的网络环境；其他容器或宿主机上的服务需使用从那里可访问的地址。

## 配置导入与导出

配置包适合迁移到另一台电脑、备份转发设置，或分享一组连接规则。它是 OriaTunnel 自己的 JSON 格式；本机 OpenSSH 配置通过「添加主机」发现，两者不是同一种导入方式。

### 导出配置

1. 在转发页选中需要导出的规则；未选择时导出当前工作区全部规则。
2. 点击「导出配置」，核对导出数量。
3. 点击「保存配置文件」，在系统对话框中选择 JSON 文件的保存位置。

导出包含所选规则、依赖的主机和跳板路线，以及名称、标签、颜色、服务协议、监听与目标等配置。应用界面导出会省略本机私钥路径。

导出不包含密码、私钥正文、私钥口令、已信任的主机密钥、SSH 源文件正文、远程命令、日志或运行状态；导出包关闭自动连接。

**导出文件仍包含服务器地址、用户名、端口和标签等连接信息。** 对外分享前检查这些内容；分享配置包不等于分享服务器的访问权限。

### 导入配置

1. 在转发页点击「导入配置」。
2. 选择或拖入一个由 OriaTunnel 导出的 JSON 文件。
3. 等待预览，选择要导入的规则，检查同名项、监听端口冲突和缺失私钥提示。
4. 为相关主机选择「导入主机配置」，或明确复用现有主机；复用会保留现有主机自己的连接设置。
5. 如果规则原来包含远程命令，由于命令不会随包迁移，需要跳过该规则，或明确选择改为仅转发（`-N`）。
6. 确认导入。补全本机认证配置，检查目标地址，再手动启动并核对指纹。

导入不会覆盖已有主机和规则；新建项生成新 ID，同名项自动编号。端口冲突提示不会替你分配新端口，启动前需要自行调整。

导入项保持停止，关闭自动连接和命令重执行，不恢复凭据、信任或旧运行状态。被来源标记为不兼容的主机，必须跳过其相关规则，或明确复用现有可连接主机。

当前接受 OriaTunnel v1 配置包，每个文件最大 2 MiB、最多 500 台主机和 1,000 条规则。配置包不会迁移应用外观、画布布局或完整应用数据。

## 后台运行、重连与自动启动

### 关闭窗口和退出

默认关闭窗口会收起到托盘或 macOS 菜单栏，转发继续运行；从托盘/菜单栏可恢复窗口、停止全部或退出。macOS 也可通过 Dock 恢复窗口。

设置中关闭「关闭窗口时收起到托盘」后，关闭窗口会直接退出。「退出 OriaTunnel」会清理所有会话、断开已有转发连接。单条规则的「停止」只影响该规则。

### 自动重连

规则高级参数可调整网络故障后的自动重连，默认开启，初始等待 2 秒，逐次增加至最多 60 秒，每轮最多 8 次。认证、指纹、监听及远程命令等需人工处理的错误不会通过无限重试解决。

网络恢复或系统唤醒后建立的是新的连接；浏览器、数据库客户端等原有 TCP 连接可能需要刷新或重新连接。停止规则会取消等待中的重试。

如明确启用远程命令，命令会随本地规则保存，请勿填写密码、令牌等秘密。命令默认不会在每次重连时重复执行；只有确认可以重复运行时，才开启对应选项。

### 登录启动与规则自动连接

这是两个独立开关，默认都关闭：

- 设置中的「开机自启」：登录系统后在后台启动应用。
- 规则中的「启动 OriaTunnel 后自动连接此规则」：让该规则在应用启动后尝试连接。

自动连接要求目标与所有跳板都已有信任，并可使用私钥或系统 Agent 认证。需要密码、私钥口令或指纹确认时会等待人工处理；勾选「记住密码」不会放宽启动自动连接的条件。

## 应用图标

设置的「外观」中可选择跟随系统、Light、Dark、Mono 图标。选项只显示图标，悬停可查看名称。跟随系统以操作系统的浅色/深色外观为准，与应用主题独立；手动选择会保留到下次启动。macOS 更新 Dock 图标，Windows 更新窗口/任务栏图标及指向当前程序的已安装快捷方式；安装包中的默认图标为 Light。托盘使用独立的透明图标，macOS 菜单栏自动适配系统明暗外观，Windows 保留彩色。

## 查看状态与排查问题

先查看规则「详情」中的实际状态和目标 TCP 可达性，再到「日志」按主机或转发筛选，也可以只显示警告。

「监听中」表示已建立监听，不证明目标应用正常；目标 TCP 可达也不代表网页、数据库或登录认证正常。D 的可达性仅表示最近一次目标请求，不代表所有代理目标。

| 现象                         | 优先检查                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| 无法连接 SSH / 超时          | SSH 地址和端口是否正确、网络是否可达、跳板路线是否完整                            |
| 认证失败                     | 用户名、认证方式、密码或私钥口令；系统 Agent 是否已加载所需身份                   |
| 指纹变化或需核对指纹         | 先确认服务器身份，核对可信指纹信息                                                |
| 本机端口监听失败             | 端口是否被其他程序或另一条规则占用，监听地址是否属于本机                          |
| R 转发被拒绝                 | 远端端口占用、SSH 服务端转发权限、允许监听的地址和端口                            |
| L 已监听但服务打不开         | 目标地址应从 SSH 服务端视角填写；目标服务是否启动，端口和协议是否正确             |
| R 已监听但公网无法访问       | 是否只监听远端回环，服务端策略、防火墙、NAT 和共享 IP 端口映射是否允许            |
| D 已监听但浏览器无法访问     | 代理是否为 SOCKS5、端口是否一致、目标是否被直连规则绕过                           |
| D 访问回环地址却打开本机服务 | 浏览器绕过了代理；调整回环代理行为或改用 L                                        |
| D 用 IP 可用、用内网域名失败 | 客户端是否把目标域名交给 SOCKS5，SSH 服务端能否解析该域名                         |
| 导入后无法启动               | 补全私钥或系统 Agent，检查端口冲突、复用主机路线，重新核对指纹                    |
| 服务协议选了 HTTPS 仍报错    | 确认服务本身提供 HTTPS，检查证书及域名；协议选择不转换服务                        |
| 「打开服务」不可用           | 是否选择协议、规则是否监听就绪、配置是否需重新连接；D 与 R 远端回环没有可直达入口 |
| 来源主机不能连接             | 查看配置诊断；不支持的路由或认证语义不能直接忽略，可按实际需要另建手动主机        |

日志页保留最近 1,000 条运行事件，支持搜索、筛选及分组，不记录密码、私钥口令、远程命令正文或业务传输内容。提交问题时可描述操作步骤、操作系统、规则类型、错误类别和脱敏后的路径，勿附上真实凭据。

## 当前功能边界

- L、R、D 均用于 TCP；D 支持 SOCKS5 CONNECT，不支持 UDP 或 SOCKS 用户认证，只允许监听 `127.0.0.1` / `::1`。
- D 不会自动接管全系统流量，也不自动配置浏览器；软件需要支持并实际使用 SOCKS5。
- SSH 加密覆盖隧道部分。从 SSH 服务端到其他目标的后续连接是否加密，取决于 HTTPS 等业务协议。
- L/R 使用非回环监听可能允许其他电脑访问，应按实际使用范围选择监听地址；服务自身的身份认证仍然有效且仍需配置。
- 支持密码、私钥、系统 SSH Agent 与有序 ProxyJump，但不提供完整系统 OpenSSH 选项兼容，也不支持任意 ProxyCommand 或远端 Agent forwarding。来源配置的限制会在主机诊断中显示。
- 配置保存在应用数据目录，凭据由受支持平台的系统凭据库另行管理；配置导出不是整个应用或系统凭据库的备份。
