# OriaTunnel 使用指南

OriaTunnel 是用于管理 SSH 端口转发的桌面应用。你可以在连接图或转发列表中管理多个服务，分别启动、停止和查看连接状态。

本指南面向日常使用，包含添加主机、创建转发、常见场景、配置迁移和问题排查。下载安装说明见 [README](../README.md#下载与安装)；如需从源码运行或继续开发，请阅读[开发指南](DEVELOPMENT.md)。

## 开始之前

准备好以下信息：

| 信息               | 用途                       | 示例                      |
| ------------------ | -------------------------- | ------------------------- |
| SSH 主机地址和端口 | 建立 SSH 连接              | `ssh.example.com:22`      |
| SSH 用户名         | 登录服务器                 | `devuser`                 |
| 认证方式           | 密码、私钥或系统 SSH Agent | 选择本机私钥文件          |
| 服务地址和端口     | 指定实际要访问的服务       | 服务器的 `127.0.0.1:3000` |

文中的域名、IP、用户名和端口均为示例，请替换为自己的配置。示例假设对应服务已经启动；OriaTunnel 默认只建立转发，不负责安装或启动数据库、网页服务等应用。

**SSH 端口与服务端口是两回事。** SSH 端口用于建立加密隧道，服务端口用于选择隧道另一端要连接的服务。SSH 登录成功后，转发还需要服务器允许，并且目标服务可从相应一侧访问。

## 选择 L、R 还是 D

| 方式                       | 使用目的                 | 监听在哪里 | 谁连接目标 | 客户端如何使用               |
| -------------------------- | ------------------------ | ---------- | ---------- | ---------------------------- |
| **L · 访问远端服务**       | 本机访问一个固定远端服务 | 此电脑     | SSH 服务端 | 访问本机监听端口             |
| **R · 让远端访问本地服务** | 远端访问一个固定本机服务 | SSH 服务端 | 此电脑     | 在远端访问监听端口           |
| **D · 动态 SOCKS5 代理**   | 借 SSH 主机访问多个目标  | 此电脑     | SSH 服务端 | 将软件配置为使用 SOCKS5 代理 |

- 访问一个数据库、网页后台或 VNC 服务：通常选择 **L**。
- 让服务器访问你电脑上的开发服务：选择 **R**。
- 用浏览器访问多个内网站点或服务器上的多个端口：可以选择 **D**。

**`127.0.0.1` / `localhost` 指哪台电脑，取决于谁连接目标。** L 的目标回环地址指 SSH 服务端；R 的目标回环地址指此电脑；D 请求中的目标回环地址在请求确实经过代理时指 SSH 服务端。D 的浏览器绕过代理问题见后文。

## 添加和管理 SSH 主机

### 从本机 SSH 配置添加

1. 点击「添加主机」，查看自动发现的候选主机，也可以搜索名称或地址。
2. 选择需要的主机并添加。
3. 查看主机详情中的地址、端口、用户名、认证方式及配置诊断。

应用读取本机 SSH 客户端配置并跟随 `Include`，包括用户的 `~/.ssh/config`（Windows 下为 `%USERPROFILE%/.ssh/config`）。设置中可以添加额外的 SSH 配置文件，并控制「自动检测配置变化」；也可以手动刷新。

发现和同步仅解析配置，不执行配置命令、不登录主机，也不会自动运行配置中的 `LocalForward`、`RemoteForward` 或 `DynamicForward`。**添加主机后，还需要在 OriaTunnel 中创建转发规则。**

来源主机的连接字段由 SSH 配置文件管理，在应用内只读。要修改地址或用户名，可以编辑源文件并刷新，或使用「创建可编辑副本」另存为手动主机。显示名称与标签可以在应用内单独设置。

### 手动添加

1. 在「添加主机」中转入手动添加。
2. 填写名称、SSH 主机地址、SSH 端口和用户名。地址栏只填主机名或 IP，端口填在单独字段中。
3. 选择认证方式：自动、密码、私钥或系统代理。使用私钥时选择本机文件，可添加多个候选私钥。
4. 按需设置标签、跳板主机、超时及保活参数。
5. 保存；需要验证时选择「保存并测试」，或保存后在主机详情点击「测试连接」。

例如，连接命令为 `ssh -p 1020 devuser@ssh.example.com` 时，对应字段为：

| 字段         | 填写内容          |
| ------------ | ----------------- |
| 名称         | 我的服务器        |
| SSH 主机地址 | `ssh.example.com` |
| SSH 端口     | `1020`            |
| 用户名       | `devuser`         |

系统代理指 **SSH Agent 认证代理**，用于使用已加载的密钥完成 SSH 认证，与 D 的 SOCKS5 网络代理不同。

### 测试连接、认证与指纹

「测试连接」只验证 SSH 连接、认证和服务器身份，不创建转发、不执行远程命令，也不代表某个业务服务已经可用。

首次连接时，根据管理员或可信渠道提供的信息核对主机密钥指纹；使用跳板时，每一跳都要分别核对。已信任的指纹发生变化时，应用拒绝连接，应先确认服务器是否重装或更换了主机密钥。

密码或加密私钥的口令在认证弹窗输入。Windows/macOS 可主动勾选「记住密码」，仅在实际密码认证成功后写入当前用户的系统凭据库；私钥口令不保存。已有保存密码时可留空复用，也可点击「清除已保存密码」。取消勾选不会删除已经保存的密码。

### 跳板与主机维护

目标主机不能直连、需要经过堡垒机时，先添加跳板主机，再在目标主机的 ProxyJump 路线中按顺序选择。每一跳使用自己的认证与指纹校验，转发目标仍由最终 SSH 服务端访问。

主机页支持搜索、筛选与分组。删除主机时会列出并一并删除关联转发、停止其连接；被其他已添加主机用作跳板的主机，需要先修改相关路线，进行中的主机测试也需先停止。删除配置来源主机只移除应用内引用，不修改本机 SSH 配置文件。

## 创建和管理转发

1. 点击「新建转发」，填写便于识别的名称，选择已添加的 SSH 主机。
2. 选择 L、R 或 D，并按下面的场景填写监听和目标字段。字段中的地址只填主机名或 IP，不填 `http://`、路径或端口。
3. L/R 可以选择 HTTP、HTTPS 或 VNC 服务协议；默认不选，再次点击可取消。D 没有固定服务入口，协议选择不可用。
4. 初次使用可以保留高级参数默认值，包括「不运行远程命令」。
5. 点击「保存」只保存规则；点击「保存并启动」继续认证和建立转发。
6. 等待规则显示「监听中」，再使用浏览器、数据库客户端或代理客户端访问。

服务协议用于「打开服务」快捷入口，**不会修改服务端口、安装服务、把 HTTP 转成 HTTPS，或改变转发的数据内容**。VNC 需要系统已有注册的客户端；noVNC 等网页入口应按实际服务选择 HTTP/HTTPS。

连接图中每条转发地址路径右侧的「打开服务」按钮，在规则就绪且入口可用时打开对应程序。R 的远端回环监听无法从此电脑直接打开；D 则需要自行配置客户端代理。

### 日常操作

- **详情**：查看实际状态、监听路径、认证方式、流量、活动连接及重试信息。
- **编辑**：修改运行中规则的连接参数会提示「保存并重新连接」，已有连接会中断；名称、颜色和服务协议修改不重连。
- **从此转发新建**：以已有规则为起点创建另一条规则，保存前检查监听端口是否冲突。
- **停止**：关闭监听、断开该规则已有业务连接，并取消重试。
- **删除与撤销**：删除会停止对应连接；本次应用运行内可撤销最近 20 次删除操作。恢复的主机和规则保持停止，自动连接关闭。

顶栏「全部开启／全部停止」作用于当前工作区全部规则。转发页可选择部分规则批量启动、停止或删除。批量启动按主机收集认证信息，各规则独立建立连接；结果中的「已受理」表示请求已提交，是否成功仍以各规则实际状态为准。

连接图和转发列表使用同一组规则。拖动节点可整理布局；此电脑上的端口也可拖到四边，双击端口可恢复自动排列。布局调整不会改变转发方向或连接参数。

## 场景一：访问服务器上的网页或数据库（L）

假设 SSH 主机上的网页后台只监听 `127.0.0.1:3000`，希望从此电脑的浏览器访问。

| 转发字段                      | 填写内容                      |
| ----------------------------- | ----------------------------- |
| 转发方式                      | L · 访问远端服务              |
| SSH 主机                      | 已添加的服务器                |
| 本机监听地址                  | `127.0.0.1`                   |
| 本机监听端口                  | `13000`                       |
| 目标地址（由 SSH 服务端访问） | `127.0.0.1`                   |
| 目标端口                      | `3000`                        |
| 服务协议                      | HTTP（假设服务本身使用 HTTP） |

保存并启动后，在此电脑打开：

```text
http://127.0.0.1:13000
```

```text
此电脑浏览器 → 本机 :13000 → SSH 隧道 → 服务器 127.0.0.1:3000
```

浏览器无需设置代理。服务器不需要把 `3000` 暴露到公网，只需 SSH 服务端能够访问该端口且允许转发。

同样的方法也适用于以下服务，每个固定目标创建一条 L 规则：

| 服务       | 本机监听示例      | 目标示例（由 SSH 服务端访问） | 客户端连接方式                                   |
| ---------- | ----------------- | ----------------------------- | ------------------------------------------------ |
| PostgreSQL | `127.0.0.1:15432` | `127.0.0.1:5432`              | 数据库客户端连接 `127.0.0.1:15432`，不选服务协议 |
| 内网网页   | `127.0.0.1:18080` | `10.20.0.15:8080`             | 浏览器打开 `http://127.0.0.1:18080`              |
| VNC        | `127.0.0.1:15900` | `127.0.0.1:5900`              | VNC 客户端指定主机 `127.0.0.1`、端口 `15900`     |

数据库或 VNC 自身的登录认证仍由对应客户端处理。如果网页会重定向到内部域名，或依赖特定域名的证书与 Cookie，还需处理应用自己的地址配置；仅转发端口不会改写网页或证书。

## 场景二：让服务器访问本机开发服务（R）

假设此电脑已运行 `127.0.0.1:3000` 的 HTTP 开发服务，希望 SSH 服务器上的程序访问它。

| 转发字段                 | 填写内容               |
| ------------------------ | ---------------------- |
| 转发方式                 | R · 让远端访问本地服务 |
| SSH 主机                 | 已添加的服务器         |
| SSH 服务端监听地址       | `127.0.0.1`            |
| SSH 服务端监听端口       | `18080`                |
| 目标地址（由此电脑访问） | `127.0.0.1`            |
| 目标端口                 | `3000`                 |

启动后，**在 SSH 服务器上**访问：

```text
http://127.0.0.1:18080
```

```text
服务器程序 → 服务器 :18080 → SSH 隧道 → 此电脑 127.0.0.1:3000
```

如果希望其他电脑也能通过服务器访问，远端监听需要使用允许外部访问的地址，同时满足 SSH 服务端的 `GatewayPorts`、`AllowTcpForwarding`、`PermitListen` 等策略、网络映射及防火墙要求。**R 显示「监听中」不等于已经获得公网入口**；共享 IP 或 NAT 环境仍可能需要管理员额外映射端口。

## 场景三：通过 SSH 代理访问多个服务（D）

D 在此电脑提供一个 SOCKS5 代理入口，由使用代理的软件在每次请求时指定目标地址和端口。

### 建立代理

| 转发字段     | 填写内容               |
| ------------ | ---------------------- |
| 转发方式     | D · 动态 SOCKS5 代理   |
| SSH 主机     | 能访问目标服务的服务器 |
| 本机监听地址 | `127.0.0.1`            |
| 本机监听端口 | `1080`                 |

D 不填写固定目标。保存并启动，等待「监听中」。

### 配置浏览器或其他客户端

在支持 SOCKS5 的浏览器代理设置或代理工具中填写：

```text
代理类型：SOCKS5
代理地址：127.0.0.1
代理端口：1080
代理认证：无
```

使用内网域名时，启用客户端的“通过 SOCKS5 代理解析 DNS”或等效选项，使客户端把域名交给代理。SSH 登录密码只在 OriaTunnel 认证时输入，不填入 SOCKS 代理的用户名或密码。

应用不会自动修改浏览器或系统代理。客户端必须实际使用该代理，且目标不能命中其直连或绕过规则。不同客户端的设置入口与能力不同，请以客户端文档为准。

### 访问不同目标

假设 SSH 服务端能够访问以下内网服务，浏览器使用代理后可直接访问：

| 服务     | 浏览器地址               |
| -------- | ------------------------ |
| 网页后台 | `http://10.20.0.15:3000` |
| 文件服务 | `http://10.20.0.15:8080` |
| 监控面板 | `http://10.20.0.16:9000` |

```text
浏览器 → 此电脑 SOCKS5 :1080 → SSH 隧道 → SSH 服务端 → 本次请求的目标
```

`1080` 是代理入口，`3000`、`8080`、`9000` 才是服务端口。浏览器地址栏不填写 `http://127.0.0.1:1080`，因为 SOCKS5 入口本身不是网页服务。

### 服务只监听服务器的回环地址怎么办？

如果服务只监听 SSH 服务端的 `127.0.0.1:3000`，SOCKS5 目标应为 `127.0.0.1:3000`，浏览器地址为 `http://127.0.0.1:3000`。**只有该请求确实经过代理时，才会连接服务器的回环地址。**

浏览器可能默认让 `localhost`、`127.0.0.1`、`::1` 绕过代理，结果连接的是此电脑。仅清空可见的“代理例外”列表，也未必能取消浏览器的隐式绕过。Chromium 的相关规则见其 [官方代理说明](https://chromium.googlesource.com/chromium/src/+/HEAD/net/docs/proxy.md#implicit-bypass-rules)。

处理方式：

1. 如果服务也监听服务器的网卡地址，使用 SSH 服务端实际能访问的该地址，并确认客户端没有绕过它。
2. 如果客户端支持让回环目标经过 SOCKS5，按客户端说明配置；这会改变该客户端访问本机地址的行为，使用结束后恢复原代理配置。
3. 如果只需访问几个固定端口，改用 L 转发，浏览器无需配置代理。

### 用 curl 单独确认代理路径

在此电脑的终端执行以下命令，需要已安装 curl，并已启动本节的 D 转发与服务器上的 HTTP 服务：

```sh
curl --max-time 15 --noproxy "" --socks5-hostname 127.0.0.1:1080 http://127.0.0.1:3000/
```

Windows PowerShell 中使用原生程序名 `curl.exe`，避免同名别名；旧版 PowerShell 对空字符串参数的传递可能不同，可在命令提示符（cmd）中运行同样的 `curl.exe` 命令。

`--socks5-hostname` 指定 SOCKS5 代理并将目标域名交给代理，`--noproxy ""` 清空本次命令的代理绕过列表，`--max-time 15` 限制等待时间。参数定义见 [curl 官方手册](https://curl.se/docs/manpage.html#--socks5-hostname)及 [noproxy 说明](https://curl.se/docs/manpage.html#--noproxy)。

预期收到服务器上该 HTTP 服务的响应；如果 curl 可用而浏览器不可用，优先检查浏览器的代理类型、端口和绕过规则。

## 场景四：共享 IP，只分配一个 SSH 端口

假设平台给你分配了 `10.0.0.8:1020`，这是一条映射到你所用服务器 SSH 服务的入口。`10.0.0.8` 在此仅为示例私网地址，不表示公网 IP；关键是此电脑可以到达它，并能通过 `1020` 建立 SSH 连接。

服务器上的多个 HTTP 服务分别监听 `127.0.0.1:3000`、`:8080`、`:9000`，没有额外对外端口。

### 主机填写方式

| 主机字段     | 填写内容              |
| ------------ | --------------------- |
| SSH 主机地址 | `10.0.0.8`            |
| SSH 端口     | `1020`                |
| 用户名       | 平台分配的 SSH 用户名 |

### 方案 A：为固定服务分别创建 L 转发

三条规则均选择上述 SSH 主机：

| 本机监听          | 目标地址（由 SSH 服务端访问） | 目标端口 | 此电脑浏览器访问         |
| ----------------- | ----------------------------- | -------- | ------------------------ |
| `127.0.0.1:13000` | `127.0.0.1`                   | `3000`   | `http://127.0.0.1:13000` |
| `127.0.0.1:18080` | `127.0.0.1`                   | `8080`   | `http://127.0.0.1:18080` |
| `127.0.0.1:19000` | `127.0.0.1`                   | `9000`   | `http://127.0.0.1:19000` |

不需要浏览器代理，也不需要平台额外开放三个服务端口。每条规则独立连接同一个 SSH 入口。

### 方案 B：一条 D 转发承载多个服务请求

选择上述 SSH 主机，建立本机 `127.0.0.1:1080` 的 D 转发，再按上一节配置浏览器 SOCKS5 代理与回环目标代理行为。之后分别访问服务器的三个服务：

```text
http://127.0.0.1:3000
http://127.0.0.1:8080
http://127.0.0.1:9000
```

```text
浏览器 → 本机 SOCKS5 :1080 → SSH 入口 10.0.0.8:1020
                              ├─ 服务器 127.0.0.1:3000
                              ├─ 服务器 127.0.0.1:8080
                              └─ 服务器 127.0.0.1:9000
```

所有这些请求都可通过 `1020` 建立的 SSH 隧道传输。不要把共享入口的 `10.0.0.8:3000` 当作该服务器的服务地址；共享入口不一定有这些端口映射。

如果 `1020` 实际只提供 HTTP、RDP 或其他非 SSH 服务，就不能用它建立 SSH 转发。如果 SSH 登录落在容器中，目标 `127.0.0.1` 指该 SSH 服务所在的网络环境；其他容器或宿主机上的服务需使用从那里可访问的地址。

## 预设远程命令

中间导航的「服务」位于「转发」之后，顶栏不再提供远程命令入口。服务页沿用主机/转发页的标题、计数、搜索工具栏和卡片布局，按服务分类分组展示，并支持分类筛选；左上角加号或空状态中的「添加服务」打开编辑器。服务只是可复用的远程命令模板：填写名称、服务颜色和服务图标，再添加启动、停止、重启、状态、日志或自定义操作。服务图标分为通用、服务品牌和 Emoji；新增 Docker、nginx、Tomcat、Jupyter、Gitea、Ollama、数据库及监控工具等本地品牌标识，也可以搜索通用图标。每个动作可填写 Shell 脚本，或使用「命令与参数」逐项填写可执行文件、参数名和参数值；参数名留空表示位置参数，参数值留空表示无参数值，不再另设勾选框；完全空白的参数行不加入命令。切换到结构化编辑时，已有脚本通过 sh -c 原样保留。

在「Shell 脚本」和「命令与参数」两种模式下，正文/参数下方都有共用的「环境变量」分组，可点击「添加环境变量」，按名称/值逐项填写，例如 `CUDA_VISIBLE_DEVICES=0,1`；变量名使用英文字母/下划线开头，后续可用数字，不能重复。变量值按字面传递，留空表示设置为空字符串；完全空白行不会保存。Shell 脚本保留原正文，执行时统一在前面生成 export，变量作用于整段多行脚本；切换编辑模式保留变量，移除全部变量恢复原脚本。普通结构化命令将这些变量只传给该命令；结构化 `systemd-run` 启动命令使用 `--setenv` 传给服务进程。它不会读取本机变量，也不会修改已有 systemd 服务的单元配置；通过 `systemctl start/restart` 管理已安装服务时，服务自身环境仍由单元配置决定。环境定义随该动作保存及导入导出，可继续修改或用垃圾桶删除。

服务卡片的禁用状态紧跟名称，命令数量与命令标签在同一行。多选框与转发列表一致，位于卡片左侧并跨两行居中；卡片不提供更多菜单或单项导出，导出统一走工具栏。执行许可使用直接按钮，启用仍需核对当前命令。卡片复选框可多选，「全选当前结果」只作用于当前搜索/分类筛选结果，改变筛选会保留其他已选项；工具栏显示总选择数，可导出所选，未选择时导出当前结果。导出沿用命令内容核对流程。批量删除先列出服务名称，确认后整组删除；有正在执行的服务、修订过期或保存失败时，整组保持不变。删除只移除模板及其引用，不删除或停止转发，也不停止远端服务。

主机项的「从此主机添加」（CopyPlus）会用当前连接设置打开新主机草稿，可修改后保存；不会复制配置来源或自动连接。服务项的「从此服务新建」会带入名称、外观、命令、环境变量和检查设置，不带转发引用；可编辑后保存，原服务保持不变。禁用服务的副本仍保持禁用。服务项的「详情」可展开查看各命令及检查设置。

服务分类可以在编辑器中调整，内置模板导入时带入分类。旧服务先按默认模板名称或明确对应的图标归类，无法判断的进入「未分类」；编辑并保存后分类固定。分类与命令脚本一起保存及导入导出。

服务页只管理模板，不选择 SSH 主机、不选择关联转发，也不直接执行命令。服务可以先保存，再由转发添加/编辑面板搜索并引用；同一模板可被多条转发复用，包括不同 SSH 主机。保存转发及模板引用是同一次配置写入，取消不更改引用。连接图转发卡片的服务命令按钮位于地址行右侧、打开服务之前；转发卡片/列表的服务菜单只显示当前转发引用的模板动作，命令在当前转发指定的 SSH 主机上执行，沿用其跳板、认证与指纹校验；需要确认或凭据时仍会提示。未引用模板的转发不显示服务入口，未被引用的模板不能独立执行。普通启停转发仍只控制网络通路。

命令支持多行脚本，可设置执行超时、允许的成功退出码及是否执行前确认。普通非交互命令限 1–3,600 秒，专用终端额外允许 0（不限时），适合持续前台服务；切回非交互命令时，0 自动改为 60 秒。停止、重启和自定义操作默认确认；修改命令后重新应用默认确认选项。「操作类型」用于分类与检查配置，不会改写脚本；切换类型会同步默认按钮名和命令块标题，保留自定义名称。执行方式默认「非交互命令」；需要 read、sudo 提示或终端程序时，选择「在专用终端执行」。专用终端使用独立 PTY + exec，不会把脚本粘贴到已有 Shell，输出合并显示。两种方式均建议使用绝对路径，或在脚本中明确初始化所需环境，不假定会加载交互 Shell 的别名和环境；不会把 SSH 密码自动交给 sudo。

点击按钮后按需认证并核对首次主机指纹。执行区域显示实时输出、stdout/stderr、退出码或退出信号，以及本次执行结果。命令成功只说明满足所配置的退出码条件；服务状态与可用性分别由显式配置的探针判断。只有认证失败且尚未提交命令时才提供补充凭据入口；断线后的未知结果不会自动重试。

「取消任务」或超时会停止本地等待并尽力关闭远端通道，不能保证远程进程及其子进程已经停止。要停止服务器上的服务，请运行你配置的停止命令。后台服务的持续运行应由服务器已有的服务管理器或脚本负责，应用不会自动增加 nohup 或后台运行参数。

执行开始会打开 SSH 终端。非交互命令可关闭输出标签或切换页面，任务继续运行；执行记录与输出可在 SSH 终端查看。专用终端的关闭行为见下节。执行中的服务不能编辑、删除或重复启动另一条命令。最近结果与输出只保留在本次应用内存中，输出超过限制时显示截断提示；清空显示只影响当前查看区域。应用退出会清理命令连接，但不会替你执行停止服务命令。

命令正文会保存在本机配置中，请勿包含密码、令牌或私钥正文。首次保存服务前会备份现有配置为同目录的 `connections.pre-commands.json`；如需降级到不支持此功能的旧构建，先退出应用，再恢复升级前的备份。v1 配置包不包含服务；如需分享服务配置，使用下文的 v2 显式选择流程。执行输出始终不导出。

新服务默认选择「不发送本机环境变量」。已有服务保留原设置；如果源主机包含 `SendEnv`，需要选择此项才能执行；这不会修改 SSH 源文件，也不会解除其他配置诊断。发现、保存、导入、应用启动和网络恢复都不会自动执行服务命令。

## SSH 交互终端

在主机列表、主机详情、连接图主机或转发操作中点击「打开 SSH 终端」，会直接连接该入口对应的 SSH 主机，不再弹出主机选择和二次连接确认；需要时才补充各跳凭据并确认首次指纹。顶栏外侧胶囊中的「SSH 终端」（与设置、关于同组）用于恢复面板；面板右上角「新建终端」可以打开另一个独立会话。同一主机也可以同时打开多个终端，最多 8 个活动终端。

终端先申请 `xterm-256color` PTY，再启动服务器的交互 Shell；服务端拒绝时会显示错误。支持 UTF-8、ANSI 颜色、滚动、查找、清屏、远端尺寸变化及 vi 等全屏程序。Shell 的环境和权限由远端账号决定。普通交互终端固定不发送本机环境变量；包含 `SendEnv` 的来源会在连接表单中说明此设置将被忽略，无需反复开启开关。其他不支持配置仍会阻止连接；专用预设终端继续遵守服务编辑器保存的环境策略。

- `Ctrl+C` 发送远端中断，`Ctrl+D` 发送 EOF，`Ctrl+Z` 挂起前台作业；`Ctrl+U` 按远端行编辑规则处理。
- 终端右键菜单提供复制、粘贴、查找、清屏；菜单显示对应快捷键，也可用菜单键或 `Shift+F10` 打开。复制使用 macOS `Cmd+C` / 其他平台 `Ctrl+Shift+C`，粘贴使用系统快捷键或 `Ctrl+Shift+V`。系统拒绝剪贴板访问时使用系统粘贴快捷键。
- 多行或含控制字符的粘贴会先展示内容，确认后才发送；单次粘贴上限 256 KiB。
- `Cmd+F` / `Ctrl+F` 打开当前终端查找；Enter / Shift+Enter 查找下一个 / 上一个，Escape 返回终端。`Cmd+K` / `Ctrl+Shift+K` 清屏；普通 `Ctrl+C/D/Z/U/L/K` 保留远端语义。

标签标题前的彩色圆点表示 Rust 会话状态：绿色已连接、灰色已结束、蓝色连接中、黄色待核对指纹/超时、红色失败；悬停标签查看文字状态。地址行只保留端点、必要的简短错误/退出信息和重连图标。

面板标题栏的「面板位置」菜单可选择靠下、靠左或靠右，并记住位置和各自的尺寸。底部拖动顶部短横条调整高度，左右拖动朝向内容区域的边缘调整宽度；聚焦分隔条后可用对应方向键、Home/End 调整。带边线的箭头用于展开/还原，面板右上角的 X 用于收起；打开/收起会沿停靠侧滑动，展开/还原会平滑调整尺寸；展开时仍能直接拉回自定尺寸。「方框加号」用于新建终端，终端标签上的 X 用于关闭该会话。折叠面板、切换页面或收起窗口不会断开会话。关闭活动终端标签需确认断开；关闭已结束标签直接移除。普通命令输出标签的关闭只结束查看。

断线、关闭终端、退出应用或更新安装都会清理对应 SSH 连接，不能保证远端进程已经停止。终端不自动重连、不重放输入；「重新连接」在原标签位置建立全新 Shell，不额外新增标签，也不重复运行已提交的预设命令。原 Shell 屏幕随新会话重置。需要跨断线保留工作时，可自行使用服务器已有的 tmux 等工具。WebView 重载会中断终端，旧屏幕不重新拼接；需要明确重新连接。

终端输入与屏幕不写入配置、前端持久状态或活动日志；服务器自身的 Shell 历史和程序日志由服务器控制。当前屏幕保留最多 5,000 行滚动历史；传输使用有界背压，界面处理较慢时暂停读取，不截断 ANSI 字节流。尚未提供 SFTP、分屏或宏录制；服务检查由下节单独配置，不从终端内容推断。

## 服务状态、健康检查与启动并连接

在服务编辑器的「服务检查与组合启动」中配置探针。所有探针均在服务的执行主机上通过 SSH 非交互执行，`localhost` 指该主机。可以仅配置健康检查，不必添加启动命令。应用不会安装服务端组件，也不在后台持续监控。

### 配置状态判定

选择一个非交互「状态」命令作为状态探针，并关闭该命令的执行前确认。默认「仅展示输出」供人查看，服务状态保持未知；需要自动判定时，选择以下方式之一：

- **退出码映射**：分别填写运行中、已停止和异常退出码，三组不能重叠。例如已有脚本约定运行中返回 0、停止返回 3，就按此填写；不要把所有非零退出码都当作停止。
- **严格 JSON**：只接受一个完整 JSON 对象，`state` 为 `running`、`stopped`、`failed` 或 `unknown`。可选 `ready` 布尔值和最长 1,024 字节的 `message` 文本；就绪仍由独立健康探针确认。命令须满足自身成功退出码条件，不能附加日志、未知字段或重复字段。

SSH 故障、无退出码、信号结束、截断、无映射或格式错误均不会解释为已停止。单次判定输入限制为 64 KiB，展示区域的输出尾部与解析输入独立。点击「检查状态」只执行一次状态探针。

### 配置健康检查

启用健康检查，填写自己的远程检查命令，并配置就绪与未就绪退出码，例如已约定的 0 / 1。命令可以调用服务器已有的服务管理器、端口工具或 HTTP 客户端。应用只依照明确映射判断，不从自然语言猜测结果；端口可达本身不证明应用功能正常。

单次检查超时为 1–30 秒，等待间隔 1–60 秒，总等待预算 1–600 秒。只有勾选「此探针只读且可安全重复」后，启动后的等待才会重复探测；未勾选时只检查一次。不要把启动、重启、写入或其他变更命令标为可重复探针。手动「检查健康」始终只执行一次。

可启用「非交互变更命令成功后检查」：启动、重启和自定义动作成功后检查状态及健康，停止动作成功后只检查状态。原命令的结果保留在步骤列表中，后检查失败不会改写先前命令的退出码。专用交互终端结束后需手动检查。

检查记录显示服务状态、健康结果、检查时间与过期标记，默认有效期 60 秒，可调整为 1–3,600 秒。服务修订、执行主机或跳板身份变化会使旧结果过期；应用重启回到未检查。过期只影响呈现，不发起 SSH 请求，也不会自动重启服务。

### 启动并连接

先选择一个非交互启动动作，并关联需要连接的转发。在服务卡片选择本次目标转发，点击「启动并连接」，核对主机、脚本、探针和转发，再提交各跳所需凭据。

1. 重新执行状态探针。运行中则跳过启动，明确停止才启动；未知或异常会暂停操作。仅展示输出的探针不能用于组合判定；没有状态探针时，每次明确执行所选启动命令。
2. 启动动作最多执行一次。若有健康探针，按已授权的重复策略等待就绪；新启动并确认就绪后再刷新已配置的状态探针，确认运行中。
3. 建立所选转发。已连接或正在连接的转发会复用，不强制重启；实际目标与跳板身份必须仍匹配。没有健康探针时允许连接，但健康结果仍显示未验证。

组合操作不会启动同一服务关联的其他转发。步骤、退出码、尝试次数和错误均在 SSH 终端中显示。同一服务的操作互斥，不会积累重复点击；同一个请求在当前应用会话内去重。转发原有的「随连接执行远程命令」须先关闭，避免与服务动作重复执行。

检查失败、未知结果、超时或取消都会停止后续步骤，不自动重复启动、不自动停止服务，也不撤销已有转发。本次新建的连接提供「停止此转发」入口，旧结果不能停止后来重建的连接；连接完成前取消时，新建连接仍可能存在，应检查转发当前状态。主动停止目标转发会取消对应尚在进行的组合操作，避免稍后又被连接。停止服务与断开转发仍是两个明确操作。

首次写入新检查配置前，若存在 E1/E2 服务配置，会备份为同目录的 `connections.pre-service-checks.json`。降级前退出应用并恢复相应升级前备份。命令、探针、关联、检查记录与输出均不随 v1 配置包导出；检查记录和输出只存在当前应用内存中。

## 配置导入与导出

配置包适合迁移到另一台电脑、备份转发设置，或分享一组连接规则。它是 OriaTunnel 自己的 JSON 格式；本机 OpenSSH 配置通过「添加主机」发现，两者不是同一种导入方式。

### 导出配置

1. 在转发页选中需要导出的规则；未选择时导出当前工作区全部规则。
2. 点击「导出配置」，核对导出数量。
3. 点击「保存配置文件」，在系统对话框中选择 JSON 文件的保存位置。

导出包含所选规则、依赖的主机和跳板路线，以及名称、标签、颜色、服务协议、监听与目标等配置。应用界面导出会省略本机私钥路径。

未勾选服务命令时保存为 v1，仅包含转发及其依赖。密码、私钥正文、私钥口令、已信任的主机密钥、SSH 源文件正文、转发原有的随连接远程命令、日志和运行状态始终排除；导出包关闭自动连接。

**导出文件仍包含服务器地址、用户名、端口和标签等连接信息。** 对外分享前检查这些内容；分享配置包不等于分享服务器的访问权限。

### 导入配置

1. 在转发页点击「导入配置」。
2. 选择或拖入一个由 OriaTunnel 导出的 JSON 文件。
3. 等待预览，选择要导入的规则，检查同名项、监听端口冲突和缺失私钥提示。
4. 为相关主机选择「导入主机配置」，或明确复用现有主机；复用会保留现有主机自己的连接设置。
5. 如果规则原来包含远程命令，由于命令不会随包迁移，需要跳过该规则，或明确选择改为仅转发（`-N`）。
6. 确认导入。补全本机认证配置，检查目标地址，再手动启动并核对指纹。

导入不会覆盖已有主机和规则；新建项生成新 ID，同名项自动编号。端口冲突提示不会替你分配新端口，启动前需要自行调整。

导入项保持停止，关闭自动连接和命令重执行，不恢复凭据、信任或旧运行状态。被来源标记为不兼容的主机，必须跳过其相关规则，或明确复用现有可连接主机。

当前接受 OriaTunnel v1/v2 配置包，每个文件最大 2 MiB、最多 500 台主机、1,000 条规则和 256 个服务。配置包不会迁移应用外观、画布布局或完整应用数据。

### 分享远程服务命令

在服务页多选后点击工具栏「导出所选」，或未选择时导出当前结果。弹窗直接列出本次服务，可调整选择并展开「核对命令与设置」查看详情；不再重复勾选包含命令。转发页导出默认只带转发，可用「包含所选服务命令」开关附加服务并选择范围。界面仅显示实际数量，命令与检查设置按分区查看。包含服务时文件为 v2，可只导出服务；仅保留本次所选转发的引用，纯服务包不包含独立主机依赖，执行主机始终由转发指定。

**服务脚本原文会进入 v2 文件。** 应用不会识别或移除脚本中的全部秘密，分享前须自行检查。凭据、主机信任、服务启用许可、检查观测及执行输出不进入配置包。旧构建会拒绝 v2；需要给旧构建使用时，不选择服务，导出 v1。

从转发页或「远程命令」点击「导入配置」，选择同一个 JSON 预览流程。服务默认不选中，须明确选择；可仅导入服务。复用主机会保留该现有主机的连接设置，请核对预览显示的实际执行端点。导入创建独立副本，重映射服务/动作/主机/规则 ID，不覆盖已有配置，关联仅保留本次选中导入的转发。

导入不会连接 SSH 或执行命令。服务统一显示「执行已禁用」，变更动作恢复执行前确认，重复健康检查及操作后检查关闭。在服务卡片点「核对并启用」，查看命令及检查设置后直接点击「启用执行」确认，不再设置「我已核对」勾选步骤；启用本身也不执行命令。普通编辑保存不能解除禁用。随后才可主动执行命令、检查、专用终端动作或「启动并连接」；需要重复探针时再明确配置授权。「禁用执行」可重新锁定空闲服务。

升级前已有服务默认保留原执行许可。首次写入 E4 字段前，应用将缺少这些字段的原配置保存为同目录的 `connections.pre-service-sharing.json`，不覆盖已有备份。降级 E3 前先退出应用、另行备份当前文件，再恢复该升级前备份；降级不会停止或回滚远端服务，升级后新配置需自行保留。

### 导入服务模板

在添加/编辑服务弹窗的标题后点击「模板导入」，按开发与协作、模型类、远程桌面、通用模板、Web 与应用、容器与基础设施、数据库与检索、缓存、消息队列、监控和对象存储分组选择，也可按名称或分类搜索；DSH 属于模型类。选中完整服务模板后导入。名称、颜色、图标、启动/停止/重启/状态/日志命令及检查设置会一起填入当前草稿；可以继续自定义名称、外观、脚本、参数和执行方式，最后点「保存」。取消模板选择保留原草稿，导入不会立即保存。内置 Tomcat、nginx、Docker Engine/容器、JupyterLab、TigerVNC、Gitea、DeepSeek Harness、Ollama、llama.cpp、vLLM、SGLang、Xinference、LMDeploy、Hugging Face TGI、TensorRT-LLM 和 LiteLLM，另有 PostgreSQL、MySQL、MariaDB、MongoDB、Elasticsearch、Redis、Valkey、Memcached、RabbitMQ、Kafka、Prometheus、Grafana 和 MinIO；通用模板仅保留 systemd 用户服务和 systemd 系统服务。Docker 容器统一归入容器与基础设施，不重复出现在通用模板中。

普通名称的模板默认使用直接命令，不要求 systemd。例如 VNC 启动为 `vncserver :1 -localhost yes`，停止为 `vncserver -kill :1`；DSH 启动为 `dsh web --port 3080`。nginx 使用 `nginx`、`nginx -s quit` 和重新加载命令；PostgreSQL 使用 `pg_ctl`；数据库、缓存等使用各自的服务端与管理 CLI。只提供服务实际支持的动作，不为每个模板硬凑五种命令。持续前台运行的启动命令自动选择「在专用终端执行」，超时默认 0（不限时），输出直接显示在 SSH 终端中。这类前台启动服务运行时，可以从服务菜单点击「停止」，结束对应专用终端会话并移除标签；也可直接关闭该标签或在终端按 Ctrl+C。停止只针对当前转发对应的启动终端，不影响其他终端。折叠 SSH 面板仍会保持运行。专用终端运行期间，启动等其他服务命令继续遵守互斥规则；停止入口保持可用，不另外发送 Shell 停止脚本。

各服务名称带「· systemd」的托管模板与通用 systemd 用户/系统服务模板，统一放在模板列表末尾的「systemd 托管」分组，不混入直接命令的各服务分类；也可搜索 systemd 或服务名称查找。系统单元应已安装，单元名须与实际部署一致；可执行启动配方使用 `systemd-run --user --collect` 创建临时用户服务（systemd 236+），并附带对应停止、重启、状态和日志动作。systemd 版本的服务生命周期由远端管理器负责。

模板中的 `/path/to/...`、模型名称、容器名和端口均为可修改示例；程序须已安装，数据库数据目录/配置和远端管理权限由用户准备，虚拟环境程序可填绝对路径。默认直接命令模板不启用自动状态映射或健康检查；状态动作仅显示 CLI 的实际结果，可按部署自行配置检查。模板不安装软件、不初始化数据库、不自动提权。

导入会替换当前草稿的名称、颜色、图标、全部操作和探针设置；保留已有服务的身份、转发引用和执行许可。通用模板中的 my-service/my-container 为示例资源名，导入后请在相关命令中改为实际资源。导入和保存均不执行脚本。结构化参数按 POSIX sh 单词引用，传给 systemd 的美元符号额外使用其字面转义；不提供隐式模板变量替换，其他工具仍可自行填写命令。

### 输出容量诊断

命令结果显示 Rust 实际保留与丢弃的字节量，以 MiB 表示。单次任务保留最近最多 2 MiB，全部命令尾部合计最多 32 MiB；超过预算优先淘汰较早已结束任务的输出，历史执行结果与防重放记录仍保留。隐藏查看时继续排空远端输出，重新打开可能只剩尾部或为空，截断不表示服务已停止。每个订阅最多一个待确认消息；这些输出只存内存，关闭/清屏不取消远端任务。交互终端另走无损背压，不能按普通文本截断 ANSI 字节。

## 后台运行、重连与自动启动

### 关闭窗口和退出

默认关闭窗口会收起到托盘或 macOS 菜单栏，转发继续运行；从托盘/菜单栏可恢复窗口、停止全部或退出。macOS 也可通过 Dock 恢复窗口。托盘菜单用分割线区分显示窗口、服务/终端、转发启停和退出四组。「服务命令」按服务名称展开具体命令，同一服务关联多个转发时，在其子菜单内按转发/主机分组并用分割线区分；未绑定模板不可执行。命令仍遵守现有确认、认证和执行许可，前台启动服务的停止会关闭对应终端。「SSH 终端」子菜单提供打开面板与已添加主机入口，不设新建终端菜单项；打开面板会恢复已有终端，无会话时进入主机选择。点击具体主机直接打开该主机终端，必要时补充认证。

设置中关闭「关闭窗口时收起到托盘」后，关闭窗口会直接退出。「退出 OriaTunnel」会清理所有会话、断开已有转发连接。单条规则的「停止」只影响该规则。

### 自动重连

规则高级参数可调整网络故障后的自动重连，默认开启，初始等待 2 秒，逐次增加至最多 60 秒，每轮最多 8 次。认证、指纹、监听及远程命令等需人工处理的错误不会通过无限重试解决。

网络恢复或系统唤醒后建立的是新的连接；浏览器、数据库客户端等原有 TCP 连接可能需要刷新或重新连接。停止规则会取消等待中的重试。

如明确启用远程命令，命令会随本地规则保存，请勿填写密码、令牌等秘密。命令默认不会在每次重连时重复执行；只有确认可以重复运行时，才开启对应选项。

### 登录启动与规则自动连接

这是两个独立开关，默认都关闭：

- 设置中的「开机自启」：登录系统后在后台启动应用。
- 规则中的「启动 OriaTunnel 后自动连接此规则」：让该规则在应用启动后尝试连接。

自动连接要求目标与所有跳板都已有信任，并可使用私钥或系统 Agent 认证。需要密码、私钥口令或指纹确认时会等待人工处理；勾选「记住密码」不会放宽启动自动连接的条件。

## 应用图标

设置的「外观」中可选择跟随系统、浅色、深色、单色图标。选项只显示图标，悬停可查看名称。跟随系统以操作系统的浅色/深色外观为准，与应用主题独立；手动选择会保留到下次启动。macOS 更新 Dock 图标，Windows 更新窗口/任务栏图标及指向当前程序的已安装快捷方式；安装包中的默认图标为浅色。托盘使用独立的透明图标，macOS 菜单栏自动适配系统明暗外观，Windows 保留彩色。

## 查看状态与排查问题

先查看规则「详情」中的实际状态和目标 TCP 可达性，再到「日志」按主机或转发筛选，也可以只显示警告。

「监听中」表示已建立监听，不证明目标应用正常；目标 TCP 可达也不代表网页、数据库或登录认证正常。D 的可达性仅表示最近一次目标请求，不代表所有代理目标。

| 现象                         | 优先检查                                                                          |
| ---------------------------- | --------------------------------------------------------------------------------- |
| 无法连接 SSH / 超时          | SSH 地址和端口是否正确、网络是否可达、跳板路线是否完整                            |
| 认证失败                     | 用户名、认证方式、密码或私钥口令；系统 Agent 是否已加载所需身份                   |
| 指纹变化或需核对指纹         | 先确认服务器身份，核对可信指纹信息                                                |
| 本机端口监听失败             | 端口是否被其他程序或另一条规则占用，监听地址是否属于本机                          |
| R 转发被拒绝                 | 远端端口占用、SSH 服务端转发权限、允许监听的地址和端口                            |
| L 已监听但服务打不开         | 目标地址应从 SSH 服务端视角填写；目标服务是否启动，端口和协议是否正确             |
| R 已监听但公网无法访问       | 是否只监听远端回环，服务端策略、防火墙、NAT 和共享 IP 端口映射是否允许            |
| D 已监听但浏览器无法访问     | 代理是否为 SOCKS5、端口是否一致、目标是否被直连规则绕过                           |
| D 访问回环地址却打开本机服务 | 浏览器绕过了代理；调整回环代理行为或改用 L                                        |
| D 用 IP 可用、用内网域名失败 | 客户端是否把目标域名交给 SOCKS5，SSH 服务端能否解析该域名                         |
| 导入后无法启动               | 补全私钥或系统 Agent，检查端口冲突、复用主机路线，重新核对指纹                    |
| 服务协议选了 HTTPS 仍报错    | 确认服务本身提供 HTTPS，检查证书及域名；协议选择不转换服务                        |
| 「打开服务」不可用           | 是否选择协议、规则是否监听就绪、配置是否需重新连接；D 与 R 远端回环没有可直达入口 |
| 来源主机不能连接             | 查看配置诊断；不支持的路由或认证语义不能直接忽略，可按实际需要另建手动主机        |

日志页保留最近 1,000 条运行事件，支持搜索、筛选及分组，不记录密码、私钥口令、远程命令正文或业务传输内容。提交问题时可描述操作步骤、操作系统、规则类型、错误类别和脱敏后的路径，勿附上真实凭据。

## 当前功能边界

- L、R、D 均用于 TCP；D 支持 SOCKS5 CONNECT，不支持 UDP 或 SOCKS 用户认证，只允许监听 `127.0.0.1` / `::1`。
- D 不会自动接管全系统流量，也不自动配置浏览器；软件需要支持并实际使用 SOCKS5。
- SSH 加密覆盖隧道部分。从 SSH 服务端到其他目标的后续连接是否加密，取决于 HTTPS 等业务协议。
- L/R 使用非回环监听可能允许其他电脑访问，应按实际使用范围选择监听地址；服务自身的身份认证仍然有效且仍需配置。
- 支持密码、私钥、系统 SSH Agent 与有序 ProxyJump，但不提供完整系统 OpenSSH 选项兼容，也不支持任意 ProxyCommand 或远端 Agent forwarding。来源配置的限制会在主机诊断中显示。
- 配置保存在应用数据目录，凭据由受支持平台的系统凭据库另行管理；配置导出不是整个应用或系统凭据库的备份。
