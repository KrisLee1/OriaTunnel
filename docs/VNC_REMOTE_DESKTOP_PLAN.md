# VNC 远程桌面实施方案

2026-11-16 · 内置 VNC 远程桌面已随 [v0.3.0](https://github.com/KrisLee1/OriaTunnel/releases/tag/v0.3.0) 发布。第 6 节保留实施前的原型记录，第 7 节定义分阶段验收。Windows x64 已验证安装注册与画面性能，Windows ARM64 已交叉构建安装包。V5 的 macOS 隔离验证与剩余验收项见[项目状态](PROJECT_STATUS.md)。

## 1. 产品范围

转发卡片提供一个 VNC 图标。首次点击时，用户选择系统默认 VNC 或应用内 VNC，然后点「此次」或「总是」打开桌面。「此次」仅对本次打开生效；「总是」保存到本机，之后直接打开。用户可以在「设置 → VNC → VNC 客户端」更改此选择。用户也可以从其他应用打开标准 VNC 链接，并在系统中选择 OriaTunnel 处理这类链接。

| 已确定的需求 | 完成时用户能做什么 |
| --- | --- |
| 自研客户端，无 noVNC 依赖 | 通过 OriaTunnel 与远端 VNC 服务完成握手、认证、画面更新和交互 |
| 独立桌面窗口 | 同时打开两个目标，在其中一个窗口断开、重连或关闭，另一个窗口继续使用 |
| 终端与文件传输 | 在当前 VNC 窗口展开已有 SSH 终端和文件传输面板，在桌面、命令行与文件之间切换 |
| 键盘、鼠标 | 输入文字和组合键，移动、点击、拖动鼠标、滚动，向远端发送 Ctrl+Alt+Del |
| 双向文本剪贴板 | 将本机文本送入远端剪贴板，在本机复制远端选中的文本；双方支持扩展协议时可传中文与多行文本 |
| 缩放 | 窗口大小变化时适应可用区域，也可按比例查看；点击位置与远端像素一致 |
| 凭据交互 | 看到目标地址和密码请求，能提交、取消、从认证失败中恢复 |

## 2. 入口、系统默认与窗口行为

1. **从转发卡片打开。** 沿用现有服务按钮的位置和可用性。通过单个桌面图标打开 VNC；有已记住的客户端时直接使用，否则弹窗选择。Rust 按规则 ID 重新检查工作进程、当前配置和监听状态，生成固定的 `vnc://主机:端口/`，按选择交给系统或直接打开内置桌面。规则已停止或配置已改变时，按钮给出具体原因。HTTP、HTTPS 沿用既有流程。[服务地址生成](../src-tauri/src/service.rs)
2. **系统选择客户端。** 用户选了第三方客户端，该客户端接收地址；选了 OriaTunnel，操作系统把地址送回 OriaTunnel 的协议入口，后者直接创建桌面窗口。没有可用处理器或打开失败时，显示系统反馈，并指向默认客户端设置。用户可以在设置中切换到应用内 VNC 后重试。
3. **设置默认客户端。** Windows 安装器把 OriaTunnel 注册为 `vnc` 候选，在应用设置点击「设置为系统默认 VNC」后跳到 Windows 默认应用页面，由用户完成选择。转发卡片的客户端偏好保存在本机，系统协议关联由这个单独的按钮发起设置。安装、升级与应用启动均须尊重既有选择。[Windows 默认应用设置](https://learn.microsoft.com/en-us/windows/apps/develop/launch/launch-default-apps-settings)
4. **收到链接。** 冷启动创建桌面窗口；应用已运行或收起到托盘时，交给现有实例创建新窗口。接受主机名、IPv4 和方括号 IPv6，省略端口取 5900，显式端口按 TCP 端口解释。拒绝嵌入凭据、路径参数、查询、片段、无效端口和超长输入。通过校验的目标由新窗口自动连接。
5. **连接与关闭。** 打开独立窗口即开始握手。服务端要求凭据时，在居中的密码面板显示目标地址，提交后继续连接。握手成功后显示桌面。断线后保留地址与重连动作。关闭桌面窗口释放该桌面会话；原有 SSH 转发继续按自己的规则运行。主窗口收起、桌面窗口关闭和应用退出分别处理。

例如，远端 VNC 监听 `127.0.0.1:5901`，OriaTunnel 已将其转发至本机 `127.0.0.1:15901`。系统客户端收到的地址应是 `vnc://127.0.0.1:15901/`。本地端口正在监听只说明 SSH 转发就绪；密码是否正确、远端桌面是否可用，需要实际 RFB 会话给出结果。

### 2.1 复用主窗口外壳与五区悬浮顶栏

VNC 桌面使用独立 Tauri 窗口，沿用主窗口的外壳容器、平台装饰配置、材质、主题和窗口控件偏好。直接组合 `WindowHeader` 与其内置的 `WindowControl`，顶栏悬浮于桌面内容上方。连接前、输入凭据、查看桌面和断线后均使用同一外壳。五个区域的位置遵循主窗口契约，以下为各区的 VNC 操作建议。[主窗口用法](../src/App.tsx) · [WindowHeader](../src/components/window/window-header.tsx) · [WindowControl](../src/components/window/window-control.tsx)

| 区域 | VNC 窗口内容 | 定位与镜像 |
| --- | --- | --- |
| 窗口控件外胶囊 | 最小化、全屏／还原、关闭当前桌面窗口 | 按现有窗口偏好位于最左或最右，与工具外胶囊交换位置 |
| 左内胶囊 `fixedLeftActions` | 留空；断线后在内容区提供重连 | 固定在窗口物理左侧，组内顺序固定 |
| 中心 `title`／`centerContent` | 单桌面显示目标主机及端口；需要可交互导航时使用中心插槽 | 以整个窗口的几何中心对齐；长标题省略并可查看全称，两侧宽度不同时仍保持居中 |
| 右内胶囊 `fixedRightActions` | 缩小、适应窗口、放大 | 固定在窗口物理右侧，组内顺序固定 |
| 桌面工具外胶囊 `children` | 文件传输、终端及「更多 → 发送 Ctrl+Alt+Del」 | 文件传输与终端沿用主窗口顶栏的图标及相邻顺序，整组按现有规则镜像 |

窗口控件在左时，从左到右为「窗口控件｜目标标题｜缩放｜桌面工具」；在右时为「桌面工具｜目标标题｜缩放｜窗口控件」。位置解析与跨窗口偏好同步复用现有设置。窄窗优先将桌面工具收入原胶囊的菜单，保留窗口控件和居中标题。[位置偏好](../src/stores/window-control-settings-store.ts) · [主窗口五区契约](ORIA_TUNNEL_DESIGN.md#32-五个位置的固定契约)

顶栏空白处沿用原生拖窗与双击最大化行为。顶栏按钮、菜单及密码输入接收本地输入；焦点由远端画布移到这些控件时释放已按下的远端按键。画布使用完整窗口高度。光标进入顶部 8 像素立即开始滑入，离开后保留 700 毫秒再收起；期间移回会取消收起。操作菜单和键盘聚焦时保持可见；跟随系统减少动态效果偏好。

### 2.2 在当前 VNC 窗口打开终端与文件传输

工具胶囊复用主窗口的 `OpenFilesButton` 和 `OpenTerminalButton workspace`。点击即在当前桌面上方展开相应的非模态面板。终端沿用 SSH 主机选择、认证、指纹确认、标签页和交互终端；文件传输沿用本机／远端文件浏览、上传下载及后台队列。两者使用现有工作区 Provider 与共享 `WorkspacePanel` 的停靠、缩放、收起和恢复交互。已打开的面板优先恢复原有标签或目录。[终端工作区](../src/features/terminal/terminal-workspace.tsx) · [文件工作区](../src/features/files/file-workspace.tsx) · [共享面板](../src/components/ui/workspace-panel.tsx)

从规则进入时，打开终端或文件面板立即使用该规则的 SSH 主机连接。系统链接优先匹配正在监听的 VNC 转发，其次匹配同地址且已添加的唯一 SSH 主机。如果没有唯一匹配，用户选一次主机即发起连接，两个面板在当前窗口共享此选择。打开 VNC 窗口本身不会发起 SSH 或 SFTP 连接，两个工具在 VNC 等待连接或断线时也可使用。

面板获得焦点时，终端按键、文件快捷键和认证输入交给当前面板；点击画布后恢复远端输入。收起面板保留当前工作内容。关闭桌面窗口时按窗口归属清理交互会话与订阅，已提交的文件传输继续由应用的同一 Rust 队列执行，可从主窗口查看和控制。

## 3. 模块、数据流与会话边界

| 层 | 职责 | 关键约束 |
| --- | --- | --- |
| 转发与协议分发 | 校验现有转发，按偏好打开系统或应用内客户端；接收系统交回的地址并创建窗口 | 收到链接后直接走窗口创建，避免再次分发导致循环 |
| Rust 会话 | 按原生窗口绑定目标和会话代次，建立 TCP，协商 RFB，处理凭据、像素与剪贴板消息 | 每个窗口只操作自己绑定的代次；停止、重载、关闭和退出都能取消正在连接、等待密码或读取画面的任务 |
| Rust 与 WebView 之间 | 以有界二进制消息传递画面矩形；按顺序传递输入与认证动作 | 慢速绘制产生背压；键按下、释放与鼠标按键的顺序须保留；相邻的普通移动可合并 |
| 独立窗口 | Canvas 更新变化区域，处理焦点、坐标映射、工具栏和密码表单 | Rust 给出握手、认证、就绪与断线结果。UI 的缩放和焦点只作用于本窗口 |
| 现有 SSH | 已启动的本地转发可直接承载 VNC；系统传入的直连地址直接访问该目标 | 复用转发已有的 SSH 认证、指纹和跳板路线。VNC 密码与 SSH 密码分别处理 |

协议数据直接经 Rust TCP 流与 RFB 服务交换。桌面窗口按窗口标签获得 VNC 会话命令、共享外壳的当前窗口操作，以及终端和文件面板实际使用的主机数据、IPC 和事件。两个 Provider 复用主应用的 Rust 状态与现有 API。接入时按窗口和终端 `clientId` 路由输入、尺寸、认证与清理；共享传输任务按任务 ID 更新，冲突对话框一次只由一个窗口处理。打开第二个窗口或重载一个窗口都须保留其他窗口的会话。主机配置管理和系统关联设置继续由主窗口处理。VNC 密码使用可清零的临时缓冲区。只有勾选「记住密码」且认证成功后才写入系统凭据库，按应用配置目录、VNC 地址及匹配的转发路线隔离。已保存密码被拒绝时重新提示；可从「更多」清除。密码、剪贴板正文及画面均不进入配置、前端持久状态或日志。

## 4. 协议、画面与交互设计

- **版本与认证。** 首批目标为 RFB 3.3、3.7、3.8，以及 None 和经典 VNC Authentication。按协商版本处理安全结果，经典密码使用服务端挑战及协议规定的 8 字节密钥规则。等待用户输密期间可以取消。失败按目标不可达、超时、认证拒绝、服务端安全类型不兼容、协议数据无效分类。经典 VNC 自身不加密画面与输入，跨网络加密沿用 SSH 转发。仅提供 VeNCrypt/TLS 或厂商专有认证的服务端需要另外实现相应安全类型；首版应明确提示实际协商结果。[RFB 规范](https://www.rfc-editor.org/rfc/rfc6143.html)
- **画面解码。** Rust 协商像素格式，实现 Raw、CopyRect、ZRLE，按同一连接的压缩字典依次解码 ZRLE 分块。只发布已校验的矩形，校验尺寸、目标和复制源边界、调色板索引、运行长度及解压上限。首次连接请求完整画面，随后请求增量。服务端发出 DesktopSize 时更新画布并重新请求完整内容。通用 zlib 和 DES 运算复用成熟基础库。[RFB 编码与扩展](https://github.com/rfbproto/rfbproto/blob/master/rfbproto.rst)
- **键鼠与缩放。** 键盘事件映射到 RFB keysym，记录物理键对应的按下值，松开时使用同一值。焦点离开或指针捕获取消时释放已按键及按钮。独立测试左右修饰键、AltGr、重复键、组合键、滚轮和跨画布边界拖动。缩放区直接提供缩小、适应窗口与放大。窗口控制区的原最大化按钮切换全屏／还原，双击顶栏空白处切换最大化／还原；固定比例从 25% 到 400%，从适应窗口切换时以实际显示尺寸为基准。坐标从实际画布矩形映射到远端像素，扣除留白与滚动偏移；本地显示比例独立于远端分辨率。
- **文本复制粘贴。** Windows 画布获得焦点后，Ctrl+C 转发复制操作并取回远端文本，Ctrl+V 发送本机文本与远端粘贴按键。经典 CutText 支持 Latin-1，扩展剪贴板协商后用 UTF-8 交换中文和多行文本。对方仅支持经典模式时，对无法表示的字符给出原因。系统剪贴板权限受限时提供可选中或粘贴的文本框。远端请求数据时只能取得用户在该会话已明确送出的文本。[扩展剪贴板规范](https://github.com/rfbproto/rfbproto/blob/master/rfbproto.rst#extended-clipboard-pseudo-encoding)

## 5. 平台与兼容策略

优先完成 Windows x64/ARM64 的构建、安装与回归。独立窗口采用第 2.1 节的共享外壳，Windows 圆角和材质遵循 OriaAide 原版平台行为。用 WebView2 验证窗口菜单、系统快捷键、显示缩放与剪贴板权限。Windows 安装器负责候选注册和卸载清理。macOS 兼容与实机测试统一安排在最终阶段 V5。

首个独立互通目标为隔离环境的 TigerVNC，记录服务端版本、安全类型、实际选中的编码和剪贴板扩展。协议夹具覆盖可重复的边界和恶意输入，独立服务端覆盖实现差异。若指定平台尚无设备证据，在交付记录中保留对应缺口。

| V5 · macOS 兼容与测试（最终阶段） | 完成 Apple Silicon/Intel 构建、系统关联适配与原生交互回归 | 在独立 Mac 测试账户完成文末的平台验收并记录结果 |

外壳验收分两步。先同时打开主窗口和两个桌面窗口，切换现有左右控件偏好，核对两个桌面的外胶囊换侧与组内镜像、内胶囊物理位置及组内顺序、标题中心与窗口中线的对齐。再用长目标名，在最小窗口、最大化、高 DPI 及深浅主题下核对各区边界与点击命中，实测拖窗、最小化、最大化／还原、关闭只作用于当前窗口；顶栏操作不会向远端发送键鼠事件，画布顶边仍可点击。

面板验收分别从应用内规则和独立系统链接进入。使用隔离 SSH 主机，在同一个 VNC 窗口完成一次交互终端命令和一次文件上传下载，核对主机选择、认证提示、文件内容及共享队列中的任务 ID。在画布与两个面板间切换焦点，验证按键只送到当前目标、收起再展开保留终端标签与文件目录。传输中关闭该桌面窗口，从主窗口继续查看任务直至完成，并确认另一窗口的终端和 VNC 会话仍可操作。

性能验证使用固定的 1080p 和 4K 夹具，分别测静态桌面、滚动、小区域频繁变化和整屏更新。记录输入到可见反馈的延迟、画面吞吐与峰值内存，重点观察慢消费者下队列有界以及断开后内存回收。转发测试仅使用独立回环 SSH 和 VNC 服务。系统关联测试宜使用一次性 Windows 用户或虚拟机，便于验证安装与卸载的实际效果。

脚本以 `-displayfd 1 -nolisten tcp -noreset -localhost -interface 127.0.0.1` 启动独立虚拟显示，使用临时 RFB 端口、24 位色深和 VncAuth。测试生成一次性密码，以标准输入交给 `vncpasswd -f`，结束时删除服务端临时认证文件。每次运行均使用新的应用数据、WebView2 配置和空 SSH 配置，在 `outputs/vnc-v2/tiger-*/` 留下截图和 `result.json`。[原生验收脚本](../scripts/qa/vnc-tigervnc.mjs)

### V4 Windows 安装与性能复测

在 Windows 上使用项目开发环境、PowerShell 7 和 WebView2，从仓库根目录构建并运行。以下命令适用于原生 x64 环境与默认 Cargo 输出目录。原生 ARM64 将模板路径中的 `nsis/x64` 换为 `nsis/arm64`。显式使用 `--target` 或自定义目标目录时，按 Tauri 的构建输出调整路径。

```powershell
pnpm tauri build --debug --bundles nsis
pwsh -NoProfile -File scripts/qa/vnc-install.ps1 -Template src-tauri/target/debug/nsis/x64/installer.nsi -CheckSettings
node scripts/qa/vnc-windows-performance.mjs src-tauri/target/debug/oria-tunnel.exe
```

安装测试使用 Tauri 生成的 NSIS 模板、实际应用二进制和安装钩子，替换测试产品名、协议名与安装目录。先在此前未注册的协议上安装、卸载，再加入能接收链接并读取 RFB 握手的外部客户端夹具，执行重装和升级。两个测试版本使用同一份应用程序。脚本核对系统设置页、注册命令、安装文件摘要、旧卸载程序的清理范围以及测试前后的真实 VNC 默认项。冷启动及驻留唤起使用 Windows Shell 和显式指定的已安装应用类，两次均核对远端像素与窗口归属。[安装与设置页脚本](../scripts/qa/vnc-install.ps1) · [链接分派夹具](../scripts/qa/vnc-installed-links.mjs)

性能测试使用独立配置，在画质模式下连接本机 RFB 3.8 服务端。两种远端分辨率分别测静止画面、CopyRect 滚动、32×32 小块与 Raw 整屏更新。输入延迟从注入鼠标移动计到 WebView2 画布读到服务端回显像素，可见更新数按浏览器重绘采样。暂停 4K 画布消费后检查服务端请求是否停止，恢复后核对末帧，关闭窗口后核对 TCP 释放并采样工作集。工作集为应用及 WebView2 子进程采样之和，共享页可能重复计数。每次测试在 `outputs/vnc-v4/` 的独立子目录保存 `result.json`。[性能脚本](../scripts/qa/vnc-windows-performance.mjs)

4K 整屏对比使用同一个性能脚本，分别传入优化前后的 x64 调试程序。两版各运行三轮，交替执行。每轮的 `continuousFull` 让服务端按请求交替发送两幅逐像素变化的 3840×2160 Raw 图案。帧序号和鼠标回显分开编码在画布标记中。预热 1 秒后，按不同间隔发送 9 次鼠标移动，持续观察至少 6 秒。服务端只在收到输入后才将回显写入下一帧。以可见帧数除以采样时长计算每轮帧率，三轮取中位数。27 次输入回显合并计算中位数。结果同时记录程序摘要、浏览器版本、实际画布尺寸及共享像素包数量。

在性能脚本的程序路径后加 `--4k-viewport`，WebView2 会创建 3840×2160、设备像素比为 1 的虚拟视口。脚本会检查整个 4K 画布按原始分辨率绘制，便于与适应窗口时的绘制开销对照。

要测整屏刷新期间的可见帧率和输入回显，在程序路径后传 `--4k-only --4k-viewport --compositor`。将 `--4k-viewport` 换成 `--enlarged-viewport` 可测 3952×2223（247/240 倍）。两种配置都从 WebView2 合成输出采集帧序号与回显像素，计时期间不读回应用画布。结果同时保留鼠标移动到达 RFB 服务端的时间、画布自身分辨率和实际显示尺寸。同样两个视口参数可单独传给 `scripts/qa/vnc-render.mjs`，验证移动矩形与整帧重绘的一致性、分段提交和全屏留白。

剩余平台验收使用独立 Windows 账户和正式产品标识。在系统设置中实际将 `vnc://` 的默认客户端从第三方切换为 OriaTunnel，直接打开回环链接并再次唤起，切回第三方后升级、卸载并重新打开链接。Windows ARM64 还需在原生设备上运行安装、链接与画面复测。

### V5 macOS 兼容与测试（最终阶段）

Windows V4 完成后，在独立 Mac 测试账户完成以下工作。

1. 构建 Apple Silicon 和 Intel 应用包，核对 `CFBundleURLTypes` 的 `vnc` 声明。实测「设为系统默认 VNC」的系统确认、第三方客户端切换、冷启动及驻留唤起、升级与卸载。[Apple URL 处理器](https://developer.apple.com/documentation/coreservices/1447760-lssetdefaulthandlerforurlscheme)
2. 在 WKWebView 上复核窗口外壳与菜单、系统快捷键、Retina 和适应窗口的点击定位。用真实系统剪贴板验证中英文多行双向往返、Latin-1 降级和权限拒绝后的手动操作。
3. 从系统链接和应用内转发分别打开桌面，用隔离的 RFB、SSH 和 SFTP 服务复测键鼠、认证、工作面板、多窗口清理和后台传输，记录设备、系统版本、性能与兼容限制。

本机回归脚本需要 macOS 12 或更新版本，以便通过 NSWorkspace 枚举 VNC 候选应用。请在仓库根目录执行以下命令。每轮使用独立标识的调试应用、临时数据目录、空 SSH 配置和回环服务。两次桌面测试应依次运行。

```sh
pnpm build
cargo build --locked --manifest-path src-tauri/Cargo.toml --example terminal_fixture
cargo test --locked --manifest-path src-tauri/Cargo.toml --lib --no-run
node scripts/qa/vnc-macos.mjs --clipboard
node scripts/qa/vnc-macos.mjs --intel
```

`--clipboard` 需要系统允许发送键盘事件，并让测试窗口保持前台。驱动在内存中暂存剪贴板项目，先验证远端中英文多行文本经系统复制、粘贴回到 RFB，再由独立进程写入不同文本，验证一次 Cmd+V 即送达一次，最后恢复原内容。默认运行仍会覆盖经典剪贴板和手动输入框。`--intel` 需要 Rust 的 `x86_64-apple-darwin` 目标，在 Apple Silicon 主机上还需要 Rosetta。每轮结果写入 `outputs/vnc-v5/native-*/result.json`。使用独立账户验收默认客户端时，仍需从未指定应用的系统链接验证确认、取消、第三方切换和卸载回退。
