## 1. 产品目标与范围

OriaTunnel 是以无限画布呈现 SSH 转发关系的桌面应用。打开后，本机卡片位于视口中央；用户创建转发，在周围按 SSH 主机生成远端卡片，每条连接保留带方向的连线和独立操作。通过卡片、端口、状态和动画，理解“入口在哪里、通过哪台 SSH 主机、最终访问什么服务”。

核心结果：创建本地转发、远程转发和动态 SOCKS5 转发；启动、停止、诊断和恢复连接；保存主机、转发规则和画布位置；原样延续 OriaAide 的窗口材质、主题与基础交互。

首版范围包括 Windows 桌面端、macOS 外壳迁移路径、TCP 转发、自动发现本机 SSH 配置、手动添加与统一主机管理、密码/私钥认证、主机指纹校验、基础连接日志和真实字节统计。Windows 先完成原生验收；macOS 需要对应设备验证后才能声明可用。系统 SSH Agent 与基础 ProxyJump 纳入主机连接阶段的验证范围；高级条件配置、任意 ProxyCommand 和完整 OpenSSH 配置兼容不作首版承诺。应用配置包导入导出与自动发现 SSH 配置是独立能力。首版不承诺 UDP、VPN/TUN、SFTP 或交互终端。

### 2.3 保持原版平台外观

源码事实：OriaAide 的 Windows 分支目前固定 `cornerRadius: 0`，模糊是原生 Acrylic 开关；macOS 路径提供模糊半径和圆角数值调节。不能把原版描述为所有平台都支持任意半径。

Windows 保持原版不透明度调节、原生 Acrylic 开关与直角行为，不新增圆角滑块、自定义轮廓或圆角适配任务。macOS 保留原版模糊半径与圆角控制。按钮、卡片与胶囊等内部组件仍保留原有主题圆角；窗口外轮廓与内部组件圆角分别处理。

### 3.2 五个位置的固定契约

| 区域 | 内容 | 位置规则 |
| --- | --- | --- |
| 外侧 A | 最小化、最大化/还原、关闭 | 随窗口控件位置设置切换到最左或最右 |
| 内侧左 | 资源侧栏、搜索/筛选 | 始终物理左侧，内部顺序不镜像 |
| 中心 | `画布 / 转发 / 主机` Tabs；设置等场景可替换为标题 | 以窗口几何中心居中 |
| 内侧右 | 新建转发、工作区运行菜单 | 始终物理右侧，内部顺序不镜像 |
| 外侧 B | 主题、外观模式、语言、设置 | 与外侧 A 交换两端，组内顺序按原版镜像；设置靠最外侧 |

镜像后的顺序：`工具控件 | 固定左 | 中心 | 固定右 | 窗口控件`。固定胶囊与中心不受镜像影响。

保留原 28px 基础按钮、胶囊 padding、主题圆角和失焦 45% 淡化。中心胶囊同样遵循材质与焦点状态。壳层背景透明度独立变化，不降低正文与按钮文字的不透明度。

现有 `title` 容器具有 `pointer-events-none`，不能直接塞入 Tabs。新增 `centerContent`，使用独立交互层；按钮/Tabs 不参与原生窗口拖动，剩余空白可拖动。双击空白最大化，双击 Tabs 不触发最大化。

通过测量左右组宽度，为中心设置对称安全区域。空间不足依次隐藏按钮文字、收纳次要工具、将 Tabs 收为当前页菜单，始终保留系统窗口按钮且不重叠。展开菜单与 Tooltip 跟随实际物理侧定位，不通过镜像文字实现换侧。

### 3.3 内容渐隐

用户指定的 shadcn scroll-fade 使用内容遮罩，支持分别设置上下宽度。普通列表、设置与日志使用同一工具；无溢出不渐隐，到达边界时恢复该边内容。[官方文档源码](https://raw.githubusercontent.com/shadcn-ui/ui/main/apps/v4/content/docs/utils/scroll-fade.mdx)

画布没有普通 scrollTop，独立实现视口遮罩：

- 主画布上沿约 80px，下沿约 28px；上沿随顶栏高度调整，紧凑窗口约 64px/20px。
- 遮罩固定在视口坐标系，不随画布缩放变化；内容向边缘溶解至原窗口材质，不覆盖白色/黑色渐变假背景。
- 只遮罩画布内容层；顶栏、底部控件、Portal、Tooltip、菜单和编辑面板不进入遮罩。
- 渐隐视觉层不截获指针；不可见区域不放可误触的隐藏按钮。通过 fitView 安全边距、键盘聚焦自动平移，使操作对象回到清晰区。
- 上下留白是 fitView/定位的安全边距，不是压缩画布面积的固定占位条。
- 侧栏/检查器内部采用更小的滚动渐隐，避免与外层叠加。

## 4. 信息架构与画布模型

### 4.1 页面与辅助面板

- **画布**：默认主界面，空间化查看与操作转发。
- **转发**：同一份规则的表格视图，便于搜索、排序、多选与批量启停；不建立第二份业务状态。
- **主机**：自动发现本机 SSH 配置与手动添加主机的统一管理界面，提供来源筛选、搜索、详情、连接测试及创建转发；详见 §4.5。
- **设置**：工具胶囊进入，包含外观、窗口、连接偏好、凭据/已信任主机、数据与关于；外观相关内容复用原组件。
- **资源侧栏**：默认收起，展示工作区、分组、主机和规则；切换工作区只切换视图，不停止其他工作区连接，并显示后台运行总数。
- **检查器**：选中卡片或连线后在右侧打开，宽约 340–400px；窄窗口使用原 ResponsiveModal。
- **活动日志**：底部可展开的浮层面板，按所选转发过滤；不把终端长日志塞入卡片。

### 4.2 节点和连线

首版使用“一个本机节点 + 每条规则一个远端节点”。同一 SSH 主机上的多条规则仍各自有卡片，避免端口、方向和状态纠缠；卡片共享主机配置引用。后续可增加按主机折叠的概览，折叠不能丢失逐条状态。

| 对象 | 内容与行为 |
| --- | --- |
| 本机卡片 | 设备名称、本机标识、运行/异常规则计数、相关端口摘要、新建转发入口；初始居中，可拖动和复位，不能删除 |
| 本地转发远端卡片 | 规则名称、SSH 主机、由 SSH 服务端访问的目标地址、状态、启停和菜单 |
| 远程转发远端卡片 | 规则名称、SSH 主机上的监听地址、由本机访问的目标地址、状态及操作 |
| 动态转发卡片 | SSH 出口主机、本地 SOCKS5 监听地址、活动连接数；目的地址标为“由客户端指定” |
| 转发边 | 规则 ID、方向、类型、端口标签、启停状态与活动效果；选中打开同一检查器 |

普通卡片建议宽 300–340px，本机约 300px；选中描边使用主题 ring。端口/IP 使用等宽数字，长名称截断并可查看完整信息。上部是标题和状态，中部是地址/端口，下部是操作与紧凑统计；不将所有配置常驻铺满卡面。

卡片状态区不得只用颜色：同时提供图标与“监听中 / 传输中 / 已停止 / 需认证 / 失败”等文字。方向类型用标签区分，不固定本地蓝、远程红等会破坏自定义主题的配色。

初始自动布局：本地转发放本机右侧，远程转发放左侧，动态代理放右下侧。实际语义取决于边箭头，不能因拖到另一侧改变转发方向。新卡按实测尺寸避让，已有手动位置保留；自动整理只在用户操作时运行。首次仅将本机置中，后续恢复视口，不在连接状态变化时自动 fitView。

复用科研画布的双击空白适应全部、双击卡片居中适应、四方向动态连接点、布局保存和高倍率显示处理。滚轮缩放、触控板平移/缩放、空格拖拽平移；节点按钮使用 nodrag/nopan 等边界，避免操作误变成拖动。

### 4.3 准确表达 SSH 转发

| 类型 | 入口与目标示例 | 画布主方向 |
| --- | --- | --- |
| 本地转发 L | 本机 `127.0.0.1:15432` → 经 SSH 主机 → `db.internal:5432` | 本机 → 远端卡片 |
| 远程转发 R | SSH 主机 `127.0.0.1:8080` → 经 SSH 连接 → 本机可达的 `127.0.0.1:3000` | 远端卡片 → 本机 |
| 动态转发 D | 本机 `127.0.0.1:1080` → SOCKS5 → SSH 主机按请求连接目的地 | 本机 → 代理出口 |

箭头表示“从监听入口到服务目标的转发关系”，业务数据在建立的 TCP 连接中双向传输；不是单向网络。SSH 登录主机也不一定等于最终服务所在主机。L 的目标主机名由服务端一侧解析，R 的目标由本机一侧解析。每张卡明确写出目标的访问侧，避免 `localhost` 歧义。上述概念依据 [OpenSSH ssh 手册](https://man.openbsd.org/ssh)。

选中连线后检查器显示三段路径：`监听入口 → SSH 通道 → 目标服务`，标出由哪一侧连接目标。后续跳板机在详细路径中单独显示，不和业务转发边混为一条可随意重连的网络拓扑。

### 4.4 连线动画

采用自定义 React Flow Edge：普通贝塞尔曲线、静态方向箭头、类型/端口标签、透明加宽命中区。React Flow 提供自定义边、标记与动画字段，但流量状态由应用提供。[React Flow Edge 文档](https://reactflow.dev/api-reference/types/edge)

- 已停止：低强调静态线。
- 连接中：低频短虚线运动，无假进度。
- 已监听且空闲：轻微沿箭头流动的虚线，明确表示“转发就绪”，不表示有真实数据。
- 有真实流量：在基础边上增加细小活动粒子或提高亮度；发送/接收指标来自真实计数。动画速度做上限限制，不按每个数据包渲染。
- 重连：警示样式与“重连中”标签；失败：静止并显示错误标识。
- 减少动态效果、窗口隐藏或边在视口外：停止循环效果，保留箭头和状态。

详情中的“发送/接收”统一以本机为参照，与 L/R 箭头无关。链路吞吐只计业务转发字节，明确不等于含加密开销的网卡流量。

### 4.5 SSH 主机管理：本机配置发现 + 手动添加

交互目标参照用户描述的 Codex 体验：打开主机页即可看到本机已有 SSH 主机别名，也可直接手动添加；用户无需先导出再导入。本节定义 OriaTunnel 自身行为，不推断 Codex 内部实现。

**发现来源与刷新**

- 默认读取当前用户的 SSH 客户端配置：Windows 为 `%USERPROFILE%/.ssh/config`，macOS 为 `~/.ssh/config`；按平台读取存在且可访问的系统客户端配置作为低优先级来源。Windows 系统客户端路径为 `%ProgramData%/ssh/ssh_config`，不是服务端的 `sshd_config`。[Microsoft 配置位置说明](https://learn.microsoft.com/en-us/windows-server/administration/openssh/openssh-server-configuration)
- 跟随 `Include` 引用及 glob 展开，保留源文件、行号与匹配顺序；正确处理相对路径、引号和路径中的空格。限制递归、检测循环和重复读取；损坏或不可读文件提供局部诊断，不导致整个主机页空白。
- 提取具体 `Host` 别名作为候选；一个 Host 行的多个具体别名分别可选。`Host *`、通配模式和否定模式只参与配置匹配，不变成虚构主机。相同别名的多个声明按配置语义合并；不同别名即使地址相同也保留，因为用户、认证或路线可能不同。
- 初次打开自动发现；监听已读取文件及相关目录的变化并防抖刷新，涵盖编辑器原子替换与新增 Include 文件；提供手动“刷新”。恢复应用焦点时检查文件变化。可在设置中关闭自动发现或添加其他客户端配置文件。
- 发现只读取配置文本和文件元信息，不读取私钥正文、不测试连接、不扫描局域网，也不从 known_hosts 或私钥文件名猜测主机。
- `Host`、`Include`、首个有效值和部分累积选项必须按各自语义处理，不能简单让后一个配置覆盖前一个；例如 IdentityFile 保留有序候选。配置原则依据 [OpenSSH 客户端配置手册](https://man.openbsd.org/ssh_config)。

列表和详情共用原版 Item、Badge、Input、Button、Tabs、ScrollArea 与 ResponsiveModal。顶栏外侧胶囊和中心位置规则保持一致；主机页固定右胶囊显示刷新/添加主机，不出现无上下文的“全部运行”。窄窗口详情改为面板，返回保留列表搜索和滚动位置。

列表显示名称/别名、user@host:port、来源标签、配置可用性、真实会话/最近测试状态和关联转发数量。来源与连接状态分开：刚发现显示“未测试”，不能显示“在线”。支持按名称、别名、地址、用户和标签搜索，按来源和需处理状态筛选。只有用户发起测试或创建转发后才建立网络连接。

**本机配置条目**

- 自动出现后可以直接用于创建转发，无需再点“导入”。主机详情展示最终解析值及来源，应用侧名称、收藏和标签作为独立元数据保存。
- 连接字段默认跟随源配置，详情提供“查看来源”“刷新”“隐藏”和“复制为手动主机”。查看来源定位文件及行号；应用不隐式重写用户的 SSH 配置。
- 隐藏只影响 OriaTunnel 中的显示，可在隐藏列表恢复；不删除源 Host 块。仍有关联规则的主机保留可定位入口。
- “复制为手动主机”固定当前已支持的解析值，生成独立 ID，原有规则继续引用原主机；不复制私钥正文，不悄悄丢弃不支持的关键连接选项。
- 源文件变化自动更新配置候选；已运行隧道继续使用本次连接的配置快照，显示“配置已更新，下次连接生效”。明确的重新连接动作才应用更新。
- 外部删除或改名时，已引用条目标为“来源已失效”，保留规则与最后解析快照供诊断，不自动删规则或用旧快照重连。用户可重新绑定主机或保存为手动主机；未经引用的条目可从发现列表移除。别名改名不根据地址猜测迁移身份。
- 读取失败与实际删除分开：暂时不可读保留旧结果并标记“同步失败”，待刷新恢复；不能把权限错误解释成主机被删除。

**手动添加条目**

表单包括显示名称、主机地址、SSH 端口（默认 22）、用户名、认证方式（密码/私钥/已支持的本机 Agent）、标签；高级项包含连接超时、保持连接和已支持的跳板设置。提供“保存”和“保存并测试”，测试失败保留填写内容。编辑只修改应用配置，删除时列出关联规则并要求先解除或重新绑定。

手动条目与发现条目并列，不因地址相同自动合并，也不覆盖本机配置。重复时提示已有主机并允许选择使用现有项。主机页的“创建转发”预选该主机，完成后跳到画布并聚焦新增卡片；只添加主机不生成未使用的画布卡片。

**配置解析与执行兼容性**

本机配置发现是首版基础能力，不延期为“高级导入”。同时明确区分“发现了别名”“解析了连接配置”和“当前引擎能按该配置连接”。

- 首版基础支持 Host/HostName/User/Port/Include/IdentityFile/IdentitiesOnly，以及实现中实际支持的超时、保活和主机校验选项；处理缺省值、路径展开及支持范围内的 Token，无法展开时明确报错。
- 主机连接阶段验证系统 Agent、IdentityAgent 与基础 ProxyJump；Windows Agent 通道和 macOS Agent 分别验收。Agent 认证不代表启用远端 agent forwarding。跳板每跳都需认证、主机校验与取消传播，拒绝循环路线。
- 对可能改变身份、路由、算法或信任的未支持选项，显示具体诊断并阻止错误降级连接。ProxyCommand、Match exec 等需要执行命令的配置不在自动发现/预览阶段执行；也不盲目使用可能求值 Match exec 的 `ssh -G` 进行后台扫描。
- 能力诊断可用“需处理”筛选定位，展示选项名、源位置与可执行操作；不把依赖跳板的主机静默当成直连主机。
- 本机配置里已有的 LocalForward/RemoteForward/DynamicForward 只展示为来源信息，不能因发现主机就自动启动或混入应用规则。
- 具体的解析支持与运行支持由同一份能力描述驱动。基础 Agent/ProxyJump 未通过平台验证时显示不可用，不伪造“已兼容本机 SSH”；高兼容性需求若超出 russh 方案，应在引擎验证阶段决定是否改用系统 OpenSSH。

## 5. 新建、修改与日常操作

### 5.1 新建转发

从本机卡片的“添加转发”、顶栏加号、空白处右键菜单或快捷键进入同一编辑面板。

1. **选择用途**：访问远端服务（L）、让远端访问本地服务（R）、通过远端代理访问（D）。显示一行具体示例，技术缩写作为辅助。
2. **选择 SSH 主机**：从自动发现与手动添加的统一列表选择，支持来源标签、搜索、刷新与“管理主机”；或就地手动新增。发现条目缺失配置或依赖不支持选项时显示原因，保留当前转发草稿。
3. **填写转发**：规则名称、监听地址/端口、目标地址/端口。D 不显示固定目标；高级项折叠。
4. **检查路径预览**：面板实时展示入口、SSH 主机、目标服务的完整语义，特别指出 localhost 属于哪台机器。
5. **保存或保存并启动**：生成远端卡片和边；缺少认证信息时停在需认证状态，不丢失填写内容。

监听默认仅本机/远端回环地址。允许选择指定网卡或所有地址时直接显示可访问范围。R 的外部访问还受服务端 GatewayPorts、AllowTcpForwarding、PermitListen 等策略及防火墙约束；不能仅凭界面选择就显示“公网已开放”。[sshd_config 手册](https://man.openbsd.org/sshd_config)

地址字段支持主机名、IPv4、IPv6；端口检查范围与同机冲突。启动前预检只能给出提示，最终以实际 bind/远端请求结果为准，不能用“预检空闲”代替启动成功。

### 5.2 修改、删除和批量动作

- 点击卡片或边：选择并显示检查器；点击启停直接执行，按钮反馈与后端真实状态同步。
- 修改名称、分组、卡片位置不重连。修改地址、端口或认证后显示“保存并重新连接”，提示当前连接会中断。
- 拖动卡片只调整布局，不改变目标；首版不开放拖线直接改路由。后续若支持拖线创建，必须进入配置面板确认完整参数。
- 复制规则时生成新身份并要求检查监听端口，默认停止；不能复制后自动抢占同一端口。
- 删除停止的规则可撤销；运行中删除明确提示会停止转发。撤销仅恢复配置和位置，不自动恢复网络监听。
- 批量启停逐项反馈，失败不阻塞已成功项；“全部”范围明确限定当前工作区，并展示数量。
- 本机卡不能删除；被规则引用的主机不能无提示删除，先列出关联规则。

### 5.3 空态、异常与长期运行

- 空画布只有本机卡与添加入口；不提供无法操作的装饰性假主机。
- 首次主机指纹显示主机/端口、算法与 SHA256 指纹；更换指纹停止并要求处理，不自动接受。
- 区分 DNS 失败、网络超时、认证失败、主机指纹变化、监听端口占用、服务端拒绝转发、目标服务拒绝连接。
- 断网进行有上限的指数退避重连；手动停止立即取消重试。认证失败或指纹变化不持续自动重试。
- 休眠唤醒检查连接，不复用失效状态。重连创建新的运行代次，旧事件不能覆盖新连接。
- 建议关闭窗口默认收起至托盘并保留隧道，首次明确提示且可改；明确“退出应用”停止全部隧道。自启动及启动后自动连接均默认关闭。
- 删除、编辑和停止对活动连接的影响应一致：首版“停止”关闭监听并终止已有转发连接；后续若增加排空停止，需要独立动作与状态。

## 6. 运行状态与诊断

将“期望状态”“实际状态”“目标健康”分开，避免把保存配置或 SSH 登录成功当成转发成功。

```text
stopped → connecting → verifying-host → authenticating → binding → listening
                           ↓                  ↓                       ↓
                      needs-attention    needs-attention          reconnecting
任何活动阶段 → stopping → stopped
不可恢复错误 → failed
```

这是状态集合示意，真实连接可跳过无需交互的阶段。`listening` 内的流量活动为 `idle / transferring`，不因单次目标失败就必然销毁仍可用的监听。

目标健康独立为 `unknown / reachable / unreachable`，附检测时间、检测位置和方式。SSH 握手成功、监听创建成功、目标 TCP 可达、应用服务正常是四种不同证据。无业务协议检查时，不声称数据库或 HTTP 应用健康。OpenSSH 的 ExitOnForwardFailure 也只针对转发建立失败，不保证后续目标连接成功。[ssh_config 手册](https://man.openbsd.org/ssh_config)

主机卡状态由真实会话聚合，不以 ICMP ping 代替 SSH 可用性。诊断提供当前监听、认证方式名称、最近错误、重试次数、活动连接、发送/接收、运行时间；无法获得的指标显示未测量，不填 0 或虚构数值。远程监听的外网可达性需要外部证据，本机内测不能替代。

## 7. 后端架构与数据所有权

### 7.1 推荐 SSH 引擎

推荐 Rust 内嵌 russh，Tokio 承接 TCP 与数据泵。理由是应用需要逐条规则生命周期、实际字节统计、异步认证和结构化错误，而不是仅展示一条 ssh 命令。

新增独立的 SSH 配置发现/解析适配器：负责本机配置文件依赖图、别名枚举、有效配置、来源定位和兼容性诊断。russh 不等于 OpenSSH 客户端配置解释器；配置解析结果必须经过引擎能力检查才能连接。自动发现、系统 Agent 与基础 ProxyJump 的验证提前到首版主机连接阶段。

库文档提供密码/公钥认证、direct-tcpip、远程监听请求/取消，以及服务端主机密钥检查和 forwarded-tcpip 回调，能够作为 L/R 的基础。D 的 SOCKS5 协商与流量计数仍需应用实现，不能声称库直接交付完整代理管理器。[russh Handle](https://docs.rs/russh/latest/russh/client/struct.Handle.html)、[russh Handler](https://docs.rs/russh/latest/russh/client/trait.Handler.html)

实施前用可控 SSH 测试环境验证 L/R、取消、半关闭、背压、断线和 Windows/macOS 私钥支持；确认后锁版本。首版每条规则独立会话，启停互不牵连；后续仅在有性能证据时按相同主机、用户、凭据与跳板路线共享会话。业务数据模型不绑定一规则一会话的永久约束。

备选是调用系统 OpenSSH，适合优先追求原配置兼容的版本；代价是逐规则流量与认证提示集成更复杂。本方案不同时维护两套运行引擎；若技术验证显示 russh 不满足必须的环境，再切换决定并更新本文。

### 7.2 模块边界

```text
React 页面 / 卡片 / 检查器
             │ 类型化命令与事件
Tauri IPC / 事件适配层
             │
Application：主机发现/同步、配置服务、TunnelManager、诊断、自动重连
             │
Core：主机、规则、端点、状态机、错误类型与端口接口
             ▲
Adapters：SSH 配置解析/文件监听、russh/Tokio、SQLite、凭据库、原生窗口与托盘
```

Core 不依赖 Tauri 或具体 SSH 库。前端不拼接 shell 命令、不自行打开 socket；运行状态以 Rust 为准。窗口壳层和 SSH 服务互不依赖，切页/重建画布不重启隧道。

### 7.3 持久化模型

| 对象 | 主要字段 | 保存规则 |
| --- | --- | --- |
| HostProfile | 稳定 id、来源类型（本机配置/手动）、显示名、别名、标签、认证引用、已支持的跳板配置 | 手动连接字段存 SQLite；发现条目保存源关联和应用元数据，无密码和私钥正文 |
| SshConfigSource | 来源 id、入口文件、依赖文件与 glob、文件修订、解析诊断 | 应用设置与可重建缓存；不改写源 SSH 配置 |
| ResolvedHost | sourceId + 别名、有效字段、逐字段来源、配置修订、能力诊断 | 可重建解析结果；应用 hostId 不依赖行号，重复扫描不产生重复主机 |
| TunnelRule | id、workspaceId、hostId、L/R/D、监听端点、目标端点、重连偏好 | SQLite；前后端共同校验，后端最终裁决 |
| Workspace | id、名称、排序、规则分组 | SQLite；首次自动建立默认工作区 |
| CanvasLayout | 稳定节点 ID、位置、视口、折叠状态 | 按工作区保存；拖动结束合并写入 |
| RuntimeSession | runId、实际状态、错误、监听信息、活动连接、本次解析配置修订及非敏感快照 | 内存为主，重启后重新建立；源更新不改动现有会话 |
| Metrics | runId、时间、双向字节和活动连接数 | 内存短窗口；日志按需轮转，不记录转发内容 |
| AppearancePreferences | 主题、模式、语言、窗口设置与面板状态 | 独立的 OriaTunnel 偏好存储 |

画布节点/边由业务配置推导，只单独保存位置、视口等 UI 状态。不能只存 React Flow 的 JSON 作为业务配置。运行态不随导入导出恢复。

配置导出默认不包含凭据；导入先校验、展示冲突和缺失认证，导入规则保持停止。私钥路径只表示本机引用，不假装可跨设备移植。SQLite 采用事务，配置与画布布局分开更新，失败时保留草稿并反馈。

### 7.4 命令与事件

命令类别：读取快照、发现/刷新主机、管理配置来源、隐藏/恢复发现条目、复制为手动主机、保存主机/规则、测试 SSH 连接、启动/停止规则、保存布局、处理主机信任、提交一次性认证、测试目标、查询日志。事件类别：发现结果变化、源配置同步失败/失效、运行态变化、认证/指纹待处理、统计批次、日志追加。

先订阅事件，再读取带序号的快照；事件包含规则 ID、runId 和递增序号，拒绝迟到响应。快速“启动→停止→启动”按规则串行调度并支持取消。统计由 Rust 每约 500–1000ms 合并推送，前端只更新对应卡片与边，不逐字节触发整个 React Flow 重渲染。

### 7.5 凭据与权限

- 私钥文件通过原生文件选择器选择，读取和解密留在 Rust；默认不复制私钥正文。
- 保存的密码/私钥口令放系统凭据库，前端仅获取凭据引用与展示名。用户新输入的秘密只在提交时短暂经过输入组件，提交后清空，不进入 Zustand 持久化、日志或错误遥测。
- 首版按需支持密码、加密/未加密私钥；系统 Agent 在主机连接阶段按平台验证，交互式多因素认证另行验证，不能根据“支持公钥”推断全部可用。
- known-hosts 信任绑定主机、端口和密钥；不能关闭严格检查来绕过首次确认。
- Tauri 命令按用途限制；导入主题只接受既有主题数据格式，不执行任意脚本。
- SOCKS5 首版绑定回环地址；允许局域网代理前需补充认证和访问控制。转发协议不自动提供 VPN 或全系统代理效果。

```text
  application/               用例、会话生命周期、重连
  adapters/ssh/              russh、TCP/SOCKS 数据泵
  adapters/ssh-config/       配置发现、解析、文件监听、来源与能力诊断
  adapters/storage/          SQLite 与偏好
  adapters/credentials/      系统凭据与私钥
  platform/                  窗口、托盘、平台适配
```

保持单一主题 Token 体系，节点、菜单、日志和设置共用原组件。布局尺寸可以有专属 Token，颜色/阴影/圆角不散落硬编码。背景点阵低对比，尽量避免卡片和顶栏同时叠多层强模糊。

卡片出现/检查器展开采用可中断的 180–280ms 过渡；直接拖动跟随指针，不做延迟追赶。流动线使用廉价 SVG/CSS 动画，界面位移使用 Motion，同一属性不交给多个引擎。支持键盘操作、焦点返回、屏幕阅读器标签；表格视图提供完整的画布替代操作入口。

建议性能验收场景：100 条规则、200 个可见节点级对象的压力样例，测量平移/缩放帧时间与内存；目标交互接近 60fps，实际结果按测试设备记录。视口外动画暂停、节点 memo、选择性订阅、日志虚拟列表；需要数据证明后再引入复杂自动布局库。

## 9. 实施顺序与验收证据

| 阶段 | 可见成果 | 验收重点 |
| --- | --- | --- |
| A：原版外壳与可运行闭环 | 原窗口、主题、五区顶栏；基本主机发现/手动添加；本机+一个真实 L 转发卡片 | 平台原版外观；居中与镜像；从发现的别名创建真实转发；独立停止与端口释放 |
| B：三种转发与主机管理 | L/R/D、新建/编辑、完整主机页、配置同步、布局保存 | Include/继承/来源诊断；系统 Agent 与基础 ProxyJump 平台验证；三种方向与 DNS 访问侧；密码/私钥/指纹；端口冲突；恢复配置不伪造运行态 |
| C：长期使用 | 重连、流量、日志、托盘、批量操作、配置导出 | 断网/休眠恢复；取消和迟到事件；日志脱敏；退出清理；目标异常与监听状态分离 |
| D：进阶能力 | 高级跳板/条件配置兼容、应用配置包导入、主机分组视图 | 按真实环境逐项验证；不以发现别名或导入文本成功代表全部语义兼容 |

A 阶段先构成一个能从界面到真实 SSH 再返回状态的最小闭环，避免先堆大量空模块。窗口、SSH 及原生界面联合验证的实际结果记录在 [项目状态](PROJECT_STATUS.md)。

视觉验收矩阵：浅色/深色/跟随系统、自定义主题、不同不透明度、失焦、工具左右镜像、中心 Tabs/标题切换、窄窗口、长语言文案、125%/150%/200% DPI、最大化/恢复、减少动态和透明效果。

网络验收矩阵：可控 SSH 服务端 + TCP 回显/HTTP 测试目标；L/R/D 的真实双向数据与字节统计、IPv4/IPv6、权限拒绝、错误密钥、目标拒绝、端口冲突、半关闭、大数据背压、取消、掉线重连和退出后的监听释放。R 的对外访问用独立客户端验证，SOCKS5 的域名模式与客户端 DNS 行为分别验证。

主机发现验收矩阵：缺少配置文件、无具体 Host、多个别名、重复 Host、通配/否定匹配、全局继承、Include 的相对路径/glob/新增/循环/权限错误、IdentityFile 多候选、Windows 空格路径、外部原子替换、删除与改名、手动条目同名、隐藏/恢复、不支持指令、运行中配置变化。以测试夹具验证解析，与隔离且确认不含命令执行的 OpenSSH 配置结果对照；扫描阶段不建立网络连接或执行配置命令。确认新增主机不会自动创建转发，来源失效不会误删关联规则或静默重连旧地址。

## 10. 方案结论与尚需验证的事项

确定的设计方向：窗口/主题保持各平台原版行为，五区悬浮顶栏，中心导航，本机居中的 React Flow 预览，按 SSH 主机组织远端卡片、组内逐规则状态和语义连线，三种转发，自动发现本机 SSH 配置与手动添加的统一主机管理，实际状态驱动视觉反馈。

技术验证集中在三处：本机 SSH 配置解析与运行引擎兼容性（包含平台 Agent、基础跳板）；russh 在目标平台的认证、L/R 与生命周期；WebView 中画布遮罩、缩放清晰度和大量动画的性能。验证失败时调整对应实现，不扩大到重新设计整个界面。

已建立最小 UI 入口与项目状态，实施过程中持续维护。当前未创建提交、远程或发布产物。
