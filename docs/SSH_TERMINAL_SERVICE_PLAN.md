# SSH 终端与远程服务命令方案

状态：E1 / E2 / E3 / E4 已实施 · 2026-10-25。Windows 原生与输入法候选交互仍待设备验收；本方案不授权连接或修改用户真实 SSH 主机。当前能力以 [项目状态](PROJECT_STATUS.md) 和源码为准。

## 1. 目标与核心决策

让用户在 OriaTunnel 内完成两类工作：打开 SSH 终端自由执行命令；把常用远程命令保存为按钮，在主机或转发旁启动、停止、重启、检查远程服务。

用户可自行填写命令。DeepSeek harness、大模型、VNC 仅是使用例子，不要求特定部署工具，不自动安装服务器组件。产品保持以 SSH 转发为中心，将远程操作作为配套能力。

推荐采用三个独立对象：

| 对象 | 职责 | 生命周期 |
| --- | --- | --- |
| SSH 主机 | 连接身份、认证、指纹、跳板路线；打开终端 | 沿用现有主机配置 |
| 远程服务 | 名称、执行主机、用户预设命令、可选状态及健康检查 | 独立保存，可不关联转发 |
| 转发 | L/R/D 网络通路；引用零个或多个远程服务，选定一个主要服务 | 转发停止不自动停止服务 |

一个远程服务可以被多个转发引用，引用共享配置、状态和操作锁。服务的执行主机不必等于转发的 SSH 主机。转发的目标地址不是可以直接登录的主机配置，不能据此猜测命令执行位置。

默认原则：用户主动点击才执行；保存、导入、发现、启动应用、恢复网络均不执行服务命令。普通“启动转发”保持原义，新增组合按钮才同时处理服务和转发。

## 2. 当前实现与需要改变的边界

本方案已核对 `src-tauri/src/{tunnel,supervisor,model,app,activity,config_export}.rs`、前端类型与桥接、UI 开发入口及组件索引。

| 当前事实 | 方案处理 |
| --- | --- |
| Tauri 2 / React 19；SSH 已锁定 russh 0.64.1 | 沿用 SSH 引擎，不增加第二套本地 ssh 进程执行体系 |
| 每条转发有独立 SSH 连接；认证、多跳、算法策略、指纹及取消均已实现 | 提取可复用的连接建立层，保持原转发的生命周期和隔离 |
| 规则已有 `no_remote_command` / `remote_command` | 旧能力保留原行为并标为“随转发执行的命令”；新服务不复用此字段 |
| 旧命令等待服务端接受请求，随后读取并丢弃输出；没有交互终端或服务就绪判定 | 新增命令任务和终端两条执行路径，分别处理退出码与 PTY |
| 来源 `SendEnv` 目前作为不支持的会话选项保留，启用旧远程命令会被阻止 | 新路径必须明确处理会话选项；不能直接删除诊断绕过 |
| 配置目前为事务式 JSON 文件；导出 v1 刻意排除命令正文 | 继续 JSON，保护真实存量配置；不借此迁移数据库 |
| 活动日志只持久化白名单生命周期字段 | 新增任务元数据，不把命令正文、终端输入、远程输出塞入活动日志 |
| 更新安装与退出通过活动任务和启动门禁清理会话 | 将新任务纳入同一门禁与清理，不遗漏终端或命令任务 |

真实影响包括：共享 SSH 建连代码抽取、新增终端依赖、保存服务命令、新增有执行能力的 IPC、输出处理与退出行为扩展。因此实施应按本文确认的边界进行，不顺带替换 SSH 引擎或重构全部状态管理。

## 3. 用户可配置什么

### 3.1 远程服务

基本字段：服务名称、执行主机、备注、关联转发。可选配置：执行环境、工作目录、状态判定、健康检查、超时及危险操作确认。

初始提供“启动 / 停止 / 重启 / 状态 / 日志”五个命令槽位，均可留空；还可添加“自定义命令”并自行命名，例如检查 GPU、重新加载配置或清理应用缓存。没有配置的操作不出现可点击的空按钮。用户不需要完整填写五个命令才可保存。

每个动作包含：

| 字段 | 建议行为 |
| --- | --- |
| 名称、类型 | 类型决定展示和组合流程；自定义动作必须显式选择是否改变远程状态，默认视为会改变 |
| 命令正文 | 多行文本，原样保留；脚本属于可执行配置，不按普通说明文字处理 |
| 执行方式 | 默认非交互命令；可选“在专用终端执行” |
| 执行环境 | 默认服务端 Shell；高级选项显式选择 POSIX sh / bash / PowerShell 等已支持配置，显示实际发送内容 |
| 工作目录 | 默认服务端登录目录；仅在已明确 Shell 类型时提供结构化路径封装 |
| 超时 | 普通动作建议 60 秒；状态查询 15 秒；模型启动可显式调整为更长时间 |
| 成功条件 | 普通动作默认退出码 0，可设置允许退出码；状态动作使用独立映射 |
| 执行后检查 | 可选择状态检查、健康检查及等待预算；不能用睡眠结束代替真实探测 |
| 确认策略 | 查询和普通启动默认直接执行；停止、重启和自定义变更默认确认，可按动作关闭 |

首次保存及命令修改后展示可审阅的“执行主机 + 命令 + 执行方式”。已保存、允许直接执行的动作无需每次重复确认；未配置认证或首次指纹仍走必要流程。关闭确认只适用于该动作当前修订，命令或执行主机变更后重新应用默认确认策略。

“状态”“日志”只是用户声明的用途，应用无法证明任意脚本没有副作用。界面不能宣称它们天然只读。只有用户明确允许重复执行的探针才可自动轮询。

### 3.2 执行环境与参数

非交互 SSH 命令不保证加载交互终端中的 alias、conda、venv 或 shell 初始化文件。编辑器说明这一点；推荐使用绝对路径或用户显式写明环境初始化。

第一版不实现通用字符串模板和任意变量替换。用户可在命令正文自行写 shell 脚本；应用不把服务名、主机名、表单文本直接插入 shell 字符串。工作目录等结构化字段由 Rust 按明确的 Shell 类型编码；不能使用一种引号规则兼容所有 Shell。默认服务端 Shell 模式下，复杂目录与环境处理由用户写入正文。

不提供保存密码、私钥口令、私钥正文的命令参数；API token 等敏感配置应使用服务器已有的受保护配置或交互输入。命令编辑器明确“内容会保存在本地配置”，可提示常见秘密格式，但不能宣称自动识别全部秘密。临时交互输入不转成保存命令。

## 4. 两个主要使用流程

### 4.1 模型服务按需启动

用户创建“模型推理”服务，选择执行主机，填写自己的启动、停止、状态命令；可设置应用健康检查，关联 API 转发。

日常操作提供：

1. **启动服务**：执行启动命令，实时查看输出；退出成功后，若配置了检查则进入“等待服务就绪”。
2. **启动并连接**：检查服务 → 必要时启动 → 等待配置的就绪条件 → 启动尚未启动的转发。服务已经就绪时跳过启动。
3. **停止服务**：显式执行停止命令；默认保留转发，便于后续重新启动服务。
4. **断开转发**：仅停止网络转发，远程服务继续运行。

如果没有状态检查，“启动并连接”明确按用户配置执行启动命令；如果没有健康检查，最多显示“启动命令成功，未验证就绪”，允许继续建立转发但不显示“服务可用”。检查失败或结果不明时，组合流程暂停，不能默认再次执行启动。

推荐让服务器已有的进程管理器负责长期服务，例如已有的 systemd 服务、容器管理或用户自己的管理脚本。普通前台 `python server.py` 会持续占用命令会话；用户可选择在终端运行，但应用不保证断开后继续运行。不自动添加 `nohup`、`&`、`disown`，不自动创建 systemd unit。

### 4.2 VNC 临时故障处理

用户创建“远程桌面”服务，填写已有的状态、重启和日志命令，关联 VNC 转发。

连接失败时可以依次检查：转发自身状态 → 远程服务状态 → 服务端口或实际应用可用性 → 日志。点击重启后展示执行输出及随后的检测结果；重启会影响远端现有用户，因此默认确认，用户可按动作设为直接执行。

VNC 通常保持运行，无须把“启动服务”绑定到每次转发连接。TCP 端口通只能表示端口可达，不能证明 VNC 登录、桌面会话或应用功能正常。

## 5. 服务、任务和连接的状态

三类状态分别展示，不能相互替代：

| 状态层 | 例子 | 依据 |
| --- | --- | --- |
| 命令任务 | 等待认证、执行中、成功、失败、取消请求、超时、结果未知 | SSH 请求确认、退出码/信号、超时、连接事件 |
| 远程服务 | 未检查、启动中、运行中、已停止、异常、未知 | 当前操作和用户配置的状态探针；保留检查时间 |
| 可用性 | 未验证、检查中、就绪、不可达、检查失败、结果过期 | 已定义的健康检查及其执行位置 |

命令请求被服务端接受不代表命令成功；退出码 0 不代表后台进程已经启动；进程运行不代表模型加载完毕；服务就绪不代表转发已连通。

普通任务状态机：准备 → 连接/指纹/认证 → 已提交 → 执行中 → 收集结果 → 完成。完成结果包含成功、失败、超时、取消或结果未知；执行后检查是独立阶段，保留原命令结果。只有拿到明确退出码或退出信号才能报告对应结果；EOF/连接关闭本身不推断成功。

状态探针有两种模式：默认只展示输出，供人查看；高级模式把退出码或用户指定的严格结构化输出映射到服务状态。未映射结果、格式错误、输出截断、SSH 故障一律是“未知/检查失败”，不能映射成“已停止”。不从自然语言或终端颜色猜测状态。

可提供简洁的自定义 JSON 约定，例如 `{"state":"running","ready":false,"message":"loading"}`；只有用户选择这一解析模式才识别它，限制长度和可接受字段，正文只作为文本显示。

状态记录携带执行主机身份、服务修订、runId、检查时间及有效期。断线、主机身份变化、服务命令修改或应用重启使旧结果过期；可显示“上次检查运行中”，不能继续当作当前状态。初始建议 60 秒后标为过期，允许按服务调整；过期本身不发网络请求。

## 6. 健康检查与组合操作

第一版主要支持用户自定义的远程检查命令；后续增加明确执行侧的 TCP/HTTP 探测，复用可复用的现有诊断能力。每个探针显示“从执行主机检查 / 从本机经转发检查”，地址中的 localhost 按这一位置解释。HTTP 默认不跟随重定向，设置超时和响应长度上限，不保存鉴权正文。

启动后的自动等待仅使用用户明确启用的可重复探针：建议每 2 秒一次、单次 5 秒上限，总预算普通服务 60 秒、模型服务可调到 10 分钟；禁止同一探针重叠。数值属于初始建议，实施时以隔离实测调整。后台持续监控默认关闭，不在应用启动时自动探测。

组合执行用 Rust 的有限步骤流程，不建设通用工作流引擎：

- 远程就绪探针：查状态 → 必要时启动 → 远程就绪 → 启动转发。
- 经转发就绪探针：查状态 → 必要时启动 → 建立转发 → 经转发验证；界面明确此时转发已连接但服务尚未确认就绪，避免循环等待。
- 转发此前已连接：复用运行状态，不强制重启。
- 步骤失败：保留各步骤结果及已经存在的资源；不自动停止远程服务，不自动撤销用户原有转发。对本次新建的转发提供明确停止入口。
- “停止服务并断开”作为后续可选组合：先确认影响的服务和所选转发，服务停止未确认时不谎报完成，不擅自停止其他引用同一服务的转发。

同一服务的变更命令互斥：执行期间禁用另一项启动、停止、重启或自定义变更，不排队积累重复点击。状态查询可单独执行，结果必须按操作代次判定，不能覆盖更新的结果。第一版建议每主机最多 4 个命令任务、全局 16 个，超过时明确提示；终端建议全局 8 个。限制可以根据实际体验调整。

对多个服务引用的转发，第一版组合按钮只操作明确选中的主要服务；其余服务单独控制，不隐式推导依赖图。独立服务对象或其他 SSH 客户端仍可能操作同一远程进程，应用无法提供跨客户端全局锁。

## 7. SSH 终端

主机列表、主机详情和画布主机卡片均提供“打开终端”；转发详情提供“SSH 主机终端”，关联服务提供“服务主机终端”，执行位置始终显示，不能混淆。

终端支持多标签，同主机可开多个会话；标签显示主机名和连接状态，内容区显示 user@host、端口及必要的跳板信息。首版支持 PTY、交互 Shell、输入输出、终端尺寸变化、UTF-8/中文输入、复制粘贴、滚动、查找、清屏、Ctrl+C/D/Z 和常见全屏程序。复杂分屏、SFTP、文件拖传和宏录制后续再评估。

使用 xterm.js 作为终端渲染组件，首次打开懒加载；Rust 通过现有 russh 请求 PTY 后启动 shell。PTY 或 shell 被服务器拒绝时给出明确错误，不能退回假终端。命令任务的“在专用终端执行”使用 PTY + exec，输入由用户控制，不把脚本偷偷粘贴到用户已有 Shell；PTY 下通常无法可靠区分 stdout/stderr，界面承认这一差异。

切页、折叠面板、收起主窗口不关闭活跃会话。关闭活跃终端标签确认断开；已结束标签直接关闭。网络断开后标签保留已显示输出并标记中断，用户可重连为新会话；不会重放已输入命令，也不会承诺恢复远程 Shell。需要跨断线保留任务时，用户可自行使用服务器已有的 tmux 等工具。

快捷键在终端聚焦时按终端语义处理：Ctrl+C 为中断；复制提供明确的跨平台快捷键与菜单。现有发布版 WebView 守卫会拦截 Ctrl+U 等按键，实施时需要精确排除终端按键路径并保留原生 devtools 禁用，不整体移除守卫。中文输入法、组合键、选择与粘贴必须在真实 WebView 验证。

## 8. 界面组织

保持现有主导航与外壳。首版不额外塞入“服务”“终端”两个顶层页面：

- 主机详情增加“远程服务”区域和“打开终端”；这里管理无关联转发的服务。
- 转发编辑增加可选的“关联服务”，可选择已有服务或就地创建，保存返回时保留转发草稿。
- 转发卡片显示主要服务名称、最近状态和一个主要动作，其余操作收进菜单；多个服务在详情展开，避免堆满画布。
- 底部提供可展开、可调整高度的工作面板，内含终端与命令输出标签；可最大化到内容区。760×520 窗口优先以内容区最大化展示，保留原窗口控件。
- 命令输出显示服务/主机、动作、起止时间、退出码、状态、stdout/stderr、检查结果及“取消任务/清空显示”。“取消任务”和“停止服务”使用不同名称。
- 执行开始自动展示对应输出；用户折叠后不因新输出反复展开。完成时简洁通知并可回到结果。自动滚动只在用户已位于底部时进行。

示意：

```text
模型 API     转发：已连接          服务：加载中 · 检查于刚刚
127.0.0.1:8000 → gpu-node:8000
[断开转发]  [查看输出]  [服务操作 ▾]

────────────────────────────────────────────────────────
[gpu-node 终端] [模型推理 · 启动] [VNC · 状态]       [最大化]
执行主机：deploy@gpu-node     命令：成功     就绪检查：等待中
远程输出……
```

复用现有 Button、Tabs、Item、Badge、HostPicker、ScrollArea、ResponsiveModal 和 Toast；终端屏幕是专用组件。继承 ORIA Token、深浅主题、八语言、可访问名称与减少动态效果。终端不叠加影响文字可读性的强透明效果，滚动区域保留选字；不改变 Windows 外壳直角行为。

## 9. 后端架构与数据

### 9.1 分层与连接隔离

```text
主机/转发入口 ─→ 终端工作面板 / 服务操作 / 输出面板
                         │ 类型化 IPC
                 应用任务注册与启动门禁
                    ┌────┴────┐
              TerminalManager CommandRunner → ServiceController
                    └────┬────┘
            共享 SSH 建连、认证、信任、多跳、取消
                         │
                    russh / Tokio
```

第一版每个终端独立 SSH 连接；每次服务操作建立独立控制连接，可供这一次操作的状态/动作/后检查顺序使用，结束后释放。控制连接不复用现有转发连接，不建设跨任务连接池。停止转发不会切断终端，命令取消不会中断其他转发。共享的是建连逻辑与既有凭据授权机制，不把多个任务绑定在同一可被误关闭的运输层上。

从 `tunnel.rs` 提取主机路线解析后的握手、认证、指纹和清理能力，转发继续调用同一实现。终端与命令不创建虚假的转发 Rule 来绕过数据模型。`supervisor.rs` 的转发自动重连不直接用于变更命令。

### 9.2 持久化及运行数据

| 数据 | 建议内容 | 存放位置 |
| --- | --- | --- |
| ServiceProfile | id、name、executionHostId、actions、statusProbe、readinessProbe、revision | 现有配置中的新增集合 |
| ServiceAction | id、kind、label、command、mode、shellProfile、cwd、timeouts、confirm、successCodes | ServiceProfile；不含秘密 |
| Rule 服务引用 | serviceIds、primaryServiceId；组合操作独立配置 | 规则新增可选字段 |
| CommandRun | runId、requestId、service/action 修订、主机身份快照、phase、exitCode/exitSignal、timestamps | Rust 内存 |
| ServiceObservation | 服务状态、就绪结果、检查时间、有效期、来源 runId | Rust 内存，重启回到未检查 |
| TerminalSession | sessionId、generation、host 快照、PTY 尺寸、phase | Rust 内存 |
| 输出与 UI | 有界字节流/文本；选中标签、面板高度 | 输出只在内存；UI 偏好可持久化 |

请求由前端传稳定动作 ID、预期修订和 requestId；Rust 再从当前配置取命令、检查主机、互斥、门禁和确认凭据。一次 requestId 在本次应用会话内去重并返回既有 runId，不能因双击或 IPC 超时重复执行。去重不构成跨进程、跨服务器的 exactly-once 保证。

新增 IPC 仅授权应用受信任的本地窗口，不向外部网页开放；输入、resize、取消和输出订阅校验任务归属与代次，限制输入块大小和请求速率。命令正文、错误输出及临时输入不进入 IPC 调试日志。终端依赖随应用打包，不动态加载远程脚本；实施时检查现有 CSP 与 capability 范围，不以放宽全局权限解决集成问题。

运行期间编辑配置只影响下一次执行；保存的修订与当前执行不同须可见。删除被服务引用的主机需要先处理引用，活动任务未结束时不能静默删除其配置。删除服务只移除应用配置和引用，明确不会卸载或停止服务器上的程序。

### 9.3 状态和输出传输

低频生命周期使用带 revision 的快照/事件；终端及命令输出走专用 Tauri Channel，不每收到一段输出就广播整个配置快照。流携带 sessionId/runId、generation、sequence，丢弃旧代次，重复片段不重复显示。

输出按字节流传输并增量解码，处理 UTF-8 跨块和 ANSI 跨块。普通命令保留 stdout/stderr 来源及接收序号，不承诺服务端两个流的精确全局先后顺序。Rust 先注册任务与订阅，再开始执行，避免首段输出丢失。

终端使用消费确认及高低水位背压；普通命令持续排空远程输出，只保留有界尾部，不因用户折叠面板而堵死命令。建议命令单次显示缓存 2 MiB、全局输出缓存 32 MiB、终端回滚 5,000 行，实施时测量并调整；达到上限显示截断标记，不把截断内容继续用于状态解析。

隐藏终端可以暂停绘制，但解析、消费和缓存仍须有界。WebView 重载与普通切页区别处理：第一版 WebView 重载时结束交互终端并标为中断，命令任务继续由 Rust 管理，可重新附着并读取有界结果；不重放任意尾部字节假装恢复完整终端屏幕。

### 9.4 会话配置兼容

来源发现保持纯解析，不执行 `Match exec`、`ProxyCommand`、`RemoteCommand` 或任何预设命令。

对当前会阻断会话的 `SendEnv`：第一版提供明确的“应用会话环境”设置，让用户选择不发送本机环境（显示与来源配置的差异）或进入后续支持的受限环境配置；选择作为应用侧元数据保存，不改 SSH 源文件。该选择只覆盖环境传递，不解除身份、路由、算法和信任诊断，也不改变旧转发命令的行为。未来若实现来源 SendEnv，须完整定义匹配、值来源及发送许可，不悄悄上传本机全部环境。

未知或未实现的会话语义继续逐项诊断。终端的 PTY 与 shell、预设命令正文必须由本次应用操作明确决定，不能暗中叠加源 RemoteCommand。

## 10. 失败、取消、权限与输出安全

### 10.1 不确定结果必须可见

- 建连或认证失败且尚未提交 exec：明确“未执行”。
- exec 已发出后断线，即使尚未收到确认：结果可能未知；禁止自动重发。
- 任务超时或取消：尽力向远端请求终止并关闭通道，显示实际收到的退出信息；没有确认时说明“本地已停止等待，远端进程状态未知”。
- 关闭 SSH 通道不保证杀死进程树，不把本地取消当作远程服务停止。
- 不使用按名字的宽泛 kill、自动 sudo 或隐式清理脚本作为取消兜底。明确的“停止服务”始终执行用户保存的停止动作。
- 重启默认执行用户配置的一条重启命令；第一版不自动拼接 stop/start。可以在自定义脚本中表达，但应用不能假装它具备事务回滚。

### 10.2 sudo 与身份

复用现有逐跳认证、指纹校验、已保存 SSH 密码的授权范围；不把 SSH 密码自动作为 sudo 密码。普通任务不靠解析密码提示自动输入；需要交互时，用户选择专用终端执行。

无交互动作可使用用户已经具备权限的命令；若用户配置了 `sudo -n`，权限不足直接失败并给出输出。应用不修改 sudoers、不默认以 root 登录、不替用户设置免密提权。交互终端中的密码输入只沿当前会话传输，客户端不记录按键；服务器自身的 Shell 历史和审计由服务器策略决定。

### 10.3 不可信输出

远程输出视为不可信文本，不作为 HTML、Markdown 指令、应用命令或本机路径操作执行。终端默认禁用远端自动剪贴板写入（OSC 52）、任意文件协议及自动打开链接；HTTP/HTTPS 链接只有用户明确点击才经既有外链校验打开。远端标题只能作为受限副标题，不能替换显示真实执行主机的身份栏。

多行粘贴默认预览确认，发送时使用支持的 bracketed paste；用户可调整提示，但不宣称 bracketed paste 能保证命令不执行。禁止远端控制序列触发应用 IPC 或执行预设动作。命令输出的复制/另存为由用户显式触发，提示其中可能包含服务器返回的敏感内容；默认不落盘、不随诊断包导出。

## 11. 应用生命周期与兼容迁移

- 收起窗口：保持终端、命令和转发，维持有界输出；不会停止远程服务。
- 正常退出/安装更新：列出转发、交互终端、进行中的命令；重新核对活动集合，阻止新任务，执行取消及有界清理。远端托管服务不会因为退出应用而自动停止。
- 退出取消或更新失败：恢复门禁；已经结束的任务不自动重放。
- 崩溃/重启：不恢复执行中的变更命令，不自动重连终端，服务回到未检查；历史记录最多表明上次任务中断。
- 网络恢复/唤醒：保留现有转发重连策略；终端和命令使用独立规则，变更动作不自动重试。

旧配置读取时新增服务集合和引用缺省为空；事务保存失败保留原文件。因用户已有实际配置，升级前保留原文件备份，降级使用升级前备份，不让旧程序覆盖丢失新字段。新字段无需随意增加版本；当配置解释规则确实无法兼容时才定义迁移版本并验证。

旧 RemoteCommand 不自动转换为服务命令，避免一次连接执行与按钮执行语义改变。可提供“复制到服务动作”的显式向导，复制后让用户决定是否关闭旧执行方式，并提示组合启动可能重复执行；不同时默认启用两套机制。

第一阶段沿用 v1 导出安全边界：不导出服务命令及会失效的服务引用，并明确提示遗漏。后续若支持服务配置分享，采用明确的新包版本：用户勾选才包含命令，导入必须预览主机与脚本，默认未启用执行、不带认证、不恢复运行态；旧版本拒绝新包优于静默丢数据。原始输出和运行记录不加入配置包。

7. 服务检查过期/未知、HTTP/TCP 检查位置、模型加载长等待、服务已运行跳过启动、无健康检查不显示就绪。
8. 收起、退出、升级安装门禁、休眠唤醒、崩溃后恢复；禁止重放变更动作。
9. 测试哨兵秘密不进入配置、活动日志、错误记录和导出；凭据只用隔离条目，测试结束清理。
10. 深浅主题、八语言、760×520、键盘导航、焦点恢复、读屏及减少动态效果。

全部连接测试使用回环 SSH 或明确隔离的测试容器/虚拟机，不使用用户真实主机；真实 systemd、PTY/full-screen 等不能由简单协议夹具证明的能力在隔离系统内验证。不用 UI 假数据或定时器模拟连接成功。

## 13. 备选方案、回退与待实施核验

选择内嵌终端及独立命令执行器，是为了统一现有主机认证、信任、多跳和输出体验。调用外部系统终端实现较快，但无法满足应用内按钮输出与统一状态；直接复用旧 RemoteCommand 无法满足独立生命周期与多动作管理。第一版连接数较多，但隔离更清晰，只有出现实际性能证据后再考虑连接池。

回退时关闭新入口，等待新任务清理，保留服务配置及备份；旧转发独立可用。共享建连层的抽取必须先通过现有集成测试；若回归，按本阶段变更回退，不改用户 SSH 配置、不撤销远端服务、不自动执行补偿命令。

实施前核验 xterm.js 当前稳定版、适配插件和许可证并锁版本；验证 russh 0.64.1 的 PTY/exec/resize/退出通知及信号行为、Tauri Channel 二进制传输和当前两平台 WebView 性能。当前本地依赖源码已有相应会话 API，但 API 存在不等于集成已验收。

### E1 实施结果（2026-10-24）

- 已实现服务配置、任意命令按钮、转发关联、逐跳认证/指纹、实时 stdout/stderr、退出码/信号、未知结果、取消、执行超时及按 requestId 去重；运行状态和缓存由 Rust 管理。
- E1 使用现有 Modal 承载配置和结果，底部多标签工作面板随 E2 终端再实施；服务关联保存在 ServiceProfile.ruleIds，避免第一阶段改动转发持久化合同。执行期间禁止修改服务，防止本次动作与编辑结果混淆。
- 当前执行方式为服务端默认 Shell 的非交互 exec，多行脚本可自行初始化环境。结构化 Shell/工作目录、PTY 执行、服务状态探针、组合启动及服务命令分享尚未开放；并未增加终端依赖。
- 单任务输出缓存 2 MiB，最多保留 16 份输出尾部；前端 ACK 限制待发送消息，关闭弹窗仍排空输出。最多 16 项活动任务、每主机 4 项，同一服务互斥；本次应用会话最多 4,096 个请求墓碑，达到上限拒绝新增，避免去重失效后重放。
- 已通过 118 项前端测试、74 项 Rust 库测试（明确跳过 3 项系统凭据测试）、5 项新增命令集成测试、11 项转发及 6 项监督集成测试；类型检查、生产构建和严格全目标 Clippy 通过。集成测试仅使用真实回环 SSH 与固定测试脚本。
- 独立标识、隔离配置的 macOS 原生应用在 760×520 完成创建/保存/关联、认证及失败后补充凭据、指纹核对、真实输出/退出码、stderr 切换、非零退出码、执行超时与取消实测，并核对深浅主题及 Escape 焦点恢复。Windows 原生、真实用户主机、E2/E3 和正式发布均不在本次验证证据内。

- Rust 有限步骤执行器使用一次独立 SSH 控制连接，顺序提交 exec，普通非交互动作也经该层执行；复用既有认证、信任、命令注册表、同服务互斥、输出 ACK 和更新/退出清理。变更动作不重试；只有明确可重复的只读健康探针才循环等待，手动检查只执行一次。后检查与原命令分别保留结果。
- 观测绑定服务修订、执行路线身份、runId、检查时间及 TTL，只存内存。配置/身份变更使旧事实过期，重启回到未检查；取消/不确定结果不宣称停止。解析输入完整且限制 64 KiB，JSON 拒绝未知/重复字段和尾随日志；退出码映射不重叠，故障、无退出码、截断与无映射均不解释为停止。
- 「启动并连接」显式选择一个关联转发，重新查状态、必要时启动一次、按授权等待就绪、建立或复用转发。新启动并就绪后刷新状态；实际主机/跳板与运行代次须匹配。不启动其他关联转发，不执行旧随连接命令，不自动停止服务或撤销既有资源；本次新建转发有明确停止入口，并核对创建时的连接代次，旧结果不能停止后来重建的连接。主动停止目标转发会取消未完成的对应组合。
- UI 复用服务编辑器、认证/确认及底部工作面板，显示服务/健康事实、时间、过期、步骤与尝试次数；八语言同步。过期刷新只读 Rust 内存，不发 SSH 请求。专用交互终端结束后手动检查，不把终端中的成功退出自动纳入服务就绪判定。
- 自动化：128 项前端测试、84 项 Rust 库测试（明确跳过 3 项系统凭据测试）；5 项 E3 真实回环集成测试，以及 5 项 exec、4 项 PTY、11 项转发和 6 项监督回归。覆盖延迟 HTTP 就绪、真实跨 SSH 主机字节传输、共享服务复用、已存在连接在健康失败后仍可用、端口不可达、部分失败、不重复启动、取消与配置变化、严格映射、备份/默认值和身份过期。最终检查结果以项目状态为准。
- macOS 独立标识/隔离数据 QA 在 760×520 已验证探针配置保存、状态退出码 3→停止、过期、逐跳凭据/指纹、延迟就绪组合、运行中跳过启动、已有转发复用、停止服务后转发仍连通。通过真实转发分别取得 HTTP 200 与 503，未连接用户真实主机或保存测试密码。
- 当前边界：健康执行侧为服务执行主机的用户命令；独立 TCP/HTTP、经本机转发的探针、后台持续监控、「停止并断开」、结构化 Shell/工作目录和服务分享仍未开放。Windows 原生验收待设备；E1–E3 的实现完成不等同于所有平台已验收或正式发布。

## 17. E4 实施边界（2026-10-25）

- 受控模板限定 POSIX sh 下的 systemd 用户/系统服务和 Docker 容器，不做通用变量替换。Rust 校验资源标识并生成完整脚本；先预览、再应用到草稿，保存/应用模板不执行命令、不安装组件、不添加 sudo。实际语法参考 [systemctl](https://www.freedesktop.org/software/systemd/man/latest/systemctl.html) 与 [Docker inspect](https://docs.docker.com/reference/cli/docker/inspect/) 官方文档。
- 显式选择服务命令才导出 v2；不选择时仍导出原 v1。v2 允许仅服务、仅规则或二者，继续使用严格白名单、2 MiB 上限和现有预览事务；旧 v1 解析器拒绝 v2。主机/规则/服务/动作 ID 重映射，服务只关联本次选中的规则。
- 导入的服务统一禁用执行，重复探针和操作后检查关闭，变更动作重新要求确认；原始脚本、执行主机、方式和探针必须可审阅，用户另行明确启用当前修订才可执行。执行门禁覆盖普通命令、专用终端、检查和组合，普通保存不能绕过启用步骤。既有服务默认保持可执行，首次写入前保留升级备份。
- 输出压力重点验证单任务/全局缓存、慢消费者、隐藏查看和多轮真实 SSH 输出；只改有证据的问题，不扩展到后台监控、SFTP、任意宏、发布或外部分享发送。
