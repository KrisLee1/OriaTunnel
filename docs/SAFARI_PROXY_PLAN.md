# Safari 使用 D 转发：待确认方案

状态：仅方案，尚未修改系统代理或实现 Safari 启动入口。2026-10-26。

## 目标与边界

用户希望从 D 转发直接打开 Safari 访问 SSH 服务端的 HTTP 服务。Chrome/Edge 可通过独立用户数据目录和启动参数实现；Safari 的代理设置进入 macOS 网络服务，不能承诺仅影响新开的 Safari 窗口。

参考：[Apple 的 macOS 代理设置](https://support.apple.com/guide/mac-help/change-proxy-settings-mchlp2591/mac)。系统 SOCKS 设置不能直接等同于 Safari 的回环请求一定经过代理；`127.0.0.1`、WebSocket、代理绕过及其他代理软件共存必须在真实 Mac 上先验证。

## 影响与授权

- 启用期间，选定网络服务上遵循系统 SOCKS 设置的其他应用及已有 Safari 窗口也可能经过这条 SSH 隧道；不是应用独占代理，也不是 VPN。
- 不自动切换网络服务、不覆盖所有网卡、不关闭其他代理软件。存在 PAC、自动发现、HTTP/HTTPS 或其他 SOCKS 设置时，先展示冲突和原值，明确选择处理方式。
- 只接受正在监听且配置未变化的 D 转发；切换目标需先恢复上一次设置。IPv4/IPv6 监听按实际地址配置，不接收任意系统命令。
- 首次启用前，在确认弹窗列出网卡/网络服务、当前与目标代理、受影响范围，以及恢复入口。只有明确确认后才修改；如系统要求认证，走原生授权，不收集或保存管理员密码。

## 备份与恢复

1. 在修改前读取选定网络服务的 SOCKS 地址、端口、启用状态、绕过列表，以及其他相关代理设置；将恢复记录原子写入应用数据目录。记录网络服务稳定标识、本次操作 ID、原值与应用将写入的值，不保存代理密码。
2. 分步骤写入并回读验证。失败时只回退本次已经成功写入且仍保持本次值的字段，保留可重试恢复记录并说明失败项。
3. 明确提供「恢复系统代理」；停止对应 D 转发和正常退出时先恢复。关闭一个 Safari 窗口不能作为结束依据，因为用户可能仍有其他 Safari 窗口。
4. 恢复使用比较后写入：仅当当前值仍与本次写入一致时恢复原值。若用户、其他代理软件或系统已经改动，不覆盖这些改动，显示冲突并保留记录。
5. 异常退出无法保证即时恢复；下次启动时检测未完成记录，先核对当前配置再提示恢复。不能承诺程序被强制结束、电脑断电或尚未重启应用时自动修复网络。
6. 切换 Wi-Fi/网线、休眠唤醒和网络服务被删除时重新检查；只恢复记录中的原服务，不向新服务复制代理配置。

## 实施与验收顺序

1. 用户确认本方案及系统范围影响后，先在真实 Mac 的隔离测试环境验证 Safari 能否通过系统 SOCKS 访问回环 HTTP、HTTPS、WebSocket，以及现有 Safari 实例。若回环地址仍绕过，停止扩大系统修改，报告限制并另选 L 转发或可达的服务地址。
2. 通过后再实现 Rust 代理管理器与持久恢复记录；前端复用现有确认弹窗、状态提示和错误 Toast，不靠定时器推断成功。
3. 测试字段写入失败、原值含代理、外部改动、D 停止/重连、正常退出、强制退出后重启、网卡切换及重复启用；不连接用户真实 SSH 主机，不自动修改用户正在使用的网络设置用于验收。

实施需要真实 Mac 及上述系统设置变更的明确授权。本轮 Windows 环境只能准备方案，不能作为 Safari 可用性或恢复成功的证据。
